# 한국어·영어 페이지 구현 및 검증

관련 이슈: [GUI-301([PlanME] 한국어·영어 페이지 분리 및 언어 전환 구성 (/ko, /en))](https://linear.app/guideme/issue/GUI-301/planme-한국어영어-페이지-분리-및-언어-전환-구성-ko-en)

## 반영한 동작

- 홈을 `/ko`, `/en`으로 제공하고 공통 화면과 언어 사전을 공유합니다. 처음 방문하는 `/`은 한국어로 이동하며, 명시적으로 선택한 언어를 쿠키로 기억합니다. 언어가 포함된 주소가 쿠키보다 우선합니다.
- 헤더의 한국어·English 링크로 전환합니다. 검색 조건, 선택한 장소, 생성된 일정 식별자와 콘텐츠 탐색 조건을 같은 탭의 세션 저장소에 보존합니다. 생성된 일정은 다시 생성하지 않고 최신 내용을 조회합니다. 생성·복원 중에는 전환을 막고 이유를 안내합니다.
- 고정 화면 문구, 오류·로딩 안내, 날짜·시간 표현과 접근성 문구를 번역했습니다. 번역이 없는 장소·콘텐츠 원문은 유지하고 영어 화면에서 원문 사용을 안내합니다.
- 장소 자동완성은 선택 언어를 Google 요청에 전달합니다. 기존 호출에서 언어를 생략하면 한국어로 동작합니다. 장소 상세 조회와 기존 일정 생성 계약은 유지합니다.
- 문서 언어, 제목·설명, 대표 주소(canonical), 언어별 대체 주소(hreflang), OpenGraph 언어와 1200×630 공유 이미지를 구성했습니다. 대표 도메인은 실제 리디렉션 목적지인 `https://www.planme.kr`입니다.
- 사용자의 최종 지시에 따라 홈 결과의 **일정 공유 페이지 열기 링크만 제거**했습니다. 상세 페이지 코드는 유지하며 기존 `/itinerary/{id}`는 `/ko/itinerary/{id}`로 이동합니다.
- 지도 로딩 실패 시 기존 예시 이미지에는 실제 경로가 아니라는 안내를 추가했습니다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| `npm run build` | 통과 |
| `npm run lint` | 오류 0개, 기존 경고 3개 |
| `PLANME_BASE_URL=http://localhost:3011 npx tsx apps/web/scripts/check-planme-locales.ts` | 언어 사전·기간 표현·원문 대체·주소 정책·HTTP 응답·메타데이터·공유 이미지 검사 통과 |
| `PLANME_BASE_URL=http://localhost:3011 npm run test:design` | 기존 상세 화면 설계 계약 검사 통과 |
| `git diff --check` | 통과 |

HTTP 검사는 `/ko`, `/en`의 200 응답과 문서 언어, 대표 주소, 언어별 대체 주소, OpenGraph 언어를 확인합니다. 두 공유 이미지의 PNG 크기는 각각 1200×630입니다. 미지원 `/fr`은 404이며, 루트의 언어 쿠키·검색 매개변수 보존, 기존 상세 주소 이동과 `/api/gpt/openapi` 응답도 확인했습니다.

브라우저에서는 실제 Google 자동완성으로 서울역을 선택하고 서울 당일 자동차 일정을 생성했습니다. 생성 중 언어 전환은 안내와 함께 차단됐습니다. 생성 완료 후 한국어에서 영어로 바꿔도 동일한 일정 식별자(`planme-v3-f6f42583-55fa-4d2f-9e3f-8f5e76f57f65`)와 이동 시간 53분·37분이 유지됐습니다. 최종 새로고침에서도 같은 결과를 확인했습니다. 홈의 상세 페이지 링크는 0개였습니다.

데스크톱 및 모바일 화면을 확인했습니다. 모바일에서 실제 문서 너비와 전체 콘텐츠 너비가 모두 375px로 측정되어 가로 넘침이 없었습니다.

## 기존 문제와 검증 한계

- 로컬 Naver 지도 인증 오류가 재현되어 실제 지도 표시 성공은 확인하지 못했습니다. 동일 문제는 기존 `docs/reports/2026-09-09-home-layout.md`에도 기록되어 있습니다. 영어 오류 안내와 예시 지도 표시를 확인했습니다.
- 별도 전체 타입 검사(`npx tsc --noEmit --project apps/web/tsconfig.json`)는 기존 `apps/web/e2e/planme-v3-widget.spec.ts:66`의 `Window` 형변환 오류(TS2352)로 실패합니다. 이번 변경 파일의 오류는 보고되지 않았고 Next.js 빌드는 통과했습니다.
- 린트의 기존 경고는 `ItineraryDashboard.tsx`의 효과 의존성 `transportMode`, 미사용 `_uiId`, 미사용 `carrymeTimeline`입니다.
- 이 기록은 로컬 작업 공간의 구현·검증 결과입니다. 운영 배포 결과를 의미하지 않습니다.

## 3000 포트 추가 UI 검증

사용자 요청에 따라 `npm --workspace @planme/web run start -- --port 3000`으로 서버를 실행하고 회사 Chrome에서 직접 조작했습니다. 아래 너비는 설정 요청값이 아닌 실제 문서의 측정값입니다.

| 화면·흐름 | 확인 결과 |
| --- | --- |
| 데스크톱 1425px | 한·영 홈, 검색 오류, 콘텐츠 분류·격자·목록 보기, 빈 결과, FAQ 네 항목, 하단 앱 버튼·푸터 표시 확인 |
| 태블릿 819px | 한·영 콘텐츠 카드, 두 열 격자, 목록 및 검색폼 배치 확인 |
| 모바일 375px | 한·영 첫 화면·검색폼, 자동완성, 기간 선택 팝업, 생성 결과·지도, 소개·제휴 배너·콘텐츠·숙박·항공·앱·이용 절차·FAQ·푸터 확인 |

| 가로 넘침·홈 링크 | 375·819·1425px에서 문서 너비와 콘텐츠 너비 일치. 홈의 상세 페이지 링크 0개 |

추가 검증에서 발견한 두 가지를 수정했습니다.

1. 모바일에서 생성 중 언어 전환 안내가 첫 화면 상단 문구와 겹쳤습니다. 홈 헤더의 고정 높이를 내용에 맞춰 늘어나는 최소 높이로 바꿨으며, 동일한 생성 중 전환 경로에서 겹침이 사라진 것을 확인했습니다.
2. 영어 콘텐츠 검색 결과 1개의 접근성 안내를 `1 items`에서 `1 item`으로 수정하고 최종 빌드 화면에서 확인했습니다.

수정 후 빌드, 언어 HTTP 검사, 기존 화면 설계 계약 검사, 변경 공백 검사가 다시 통과했습니다. 린트는 오류 0개와 앞서 기록한 기존 경고 3개입니다. 영상 내 문자와 브라우저 기본 미디어 컨트롤, Naver가 제공하는 지도 지명·기본 제어 문구는 서비스 자체 번역 범위에 포함되지 않습니다. 제휴 사이트 이동 후 예약·결제 흐름은 이번 검증 대상에 포함하지 않았습니다.

## 기간 선택창 바깥 클릭 수정

추가 사용자 제보로 기간 선택창 바깥 클릭 누락을 확인했습니다. 팝업 루트의 `pointerEvents: none` 설정이 기본 바깥 클릭 닫기를 막고, 별도 클릭 처리는 검색 영역 안에서만 실행되는 구조였습니다. 이 예외 설정과 별도 처리를 제거하여 [MUI Popover의 기본 바깥 클릭 닫기](https://mui.com/material-ui/react-popover/)를 사용합니다.

수정 빌드가 통과했고 3000 포트에 재시작했습니다. 데스크톱·모바일 모두 검색 영역 바깥 배경 클릭 후 창이 닫히고 선택한 1박 2일이 유지되는 것을 직접 확인했습니다. 내부 증가 버튼은 창을 유지하면서 기간을 변경하며 Escape 닫기도 확인했습니다.

## 검색 결과와 해외여행 준비 화면 디자인 조정

배포 전 사용자 의견에 따라 두 결과 화면을 홈의 색상과 카드 스타일에 맞췄습니다. 결과 전용 테마에서 제목은 `#124b97`, 본문은 `#31577d`, 보조 문구는 `#62738c`를 사용합니다. 해외여행 준비 카드 6개는 `#f5f9ff` 배경과 연한 파란 테두리·아이콘으로 통일하고 홈 콘텐츠 너비에 맞췄습니다. 일정표는 글자 굵기와 그림자를 줄이고 아이콘 배경을 연하게 바꿨으며, 경로 구분용 파랑·초록은 유지했습니다. 생성 진행 화면의 제목도 같은 파란색으로 맞췄습니다.

실제 서울 1박 2일 자동차 일정 생성 후 한국어 데스크톱과 영어 모바일 결과를 확인했습니다. 최종 브라우저 계산 스타일에서 결과 제목이 `rgb(18, 75, 151)`이고 일정 아이콘 배경이 연한 파랑임을 확인했습니다. 서울역→Paris 준비 화면에서도 한·영 제목과 카드 6개의 배경색을 확인했습니다. 모바일 375px·데스크톱 1425px에서 가로 넘침이 없었습니다. 빌드·언어 검사·기존 화면 설계 계약 검사가 통과했고 린트는 기존 경고 3개 외 오류가 없었습니다. 이 시점에는 PR 생성·병합·운영 배포를 실행하지 않았습니다.
