## 구현과 미확정 항목 처리

- 대표 문구·기존 검색·일정 안내·소개 영상·제휴 배너·콘텐츠 탐색·숙소/항공 안내·앱 다운로드·이용 과정·FAQ·앱 소개 순서.
- 검색창의 입력값, 장소 선택 세션, 중복 제출 방지, 서버 액션, 국내 일정 상세 이동과 해외 안내를 유지한다. 검색 화면의 외곽 배치만 분리했다.
- 데스크톱 검색 한 행, 태블릿 2열, 모바일 1열. 콘텐츠는 화면 폭에 맞춰 3/2/1열로 표시한다.
- 콘텐츠 탭·검색·격자/목록 전환, 빈 검색 복구, FAQ 펼치기, 제휴 배너 전환·일시정지 구현. 탭은 방향키/Home/End를 지원한다. 자동 배너는 숨겨진 문서·포커스/마우스 진입·동작 줄이기 설정을 고려한다.
- 매거진은 전달받은 `articles` 속성으로 표시할 수 있도록 영역만 준비했다. 기본 데이터는 없으며 하단 기사 영역은 숨긴다. 사용자가 직접 매거진 탭을 선택했을 때만 빈 상태를 안내한다. 이는 질문 백로그 기존 Q-003의 미노출 답변을 반영한다.
- 최초 방문의 임의 일정은 만들지 않는다. 일정 영역에는 검색 안내를 두고 실제 검색 결과는 기존 상세 화면에서 표시한다. 홈 내 결과 표시 여부는 Q-004에 남겼다.
- 대표 사진 미확정으로 기존 PlanME 배경을 재사용한다. 소개 영상과 이미지의 최종 선정은 Q-005에 남겼다.
- 확인된 스토어 주소로 앱 다운로드를 연결한다. 별도 캠페인 주소 여부는 Q-006에 남겼다.
- 뉴스레터 수집/성공 표시와 입력창은 노출하지 않는다. 외부 구독 페이지와 기능 준비 전 노출 정책은 Q-007에 남겼다.
- 실제 할인·예약 가능 여부를 확인하지 못한 가격/수치/통계/할인 보장 문구를 넣지 않았다. 앱의 정적 호텔 예시 데이터도 가져오지 않았다.

## 검증

- `npm run lint`: 오류 없음. 변경하지 않은 `ItineraryDashboard.tsx`에 기존 경고 3건.
- `npm run build`: Next.js 16.2.9 컴파일·TypeScript·페이지 생성 통과.
- `git diff --check`: 통과.
- Chrome 회사 프로필에서 `http://localhost:3015/` 직접 확인. 뷰포트 1680×2027, 768×1024, 390×844에서 화면 캡처 검토. 문서 가로 폭은 각각 1665, 753, 375px로 가로 넘침 없음.
- 빈 여행 검색 시 출발지·목적지·기간·이동수단 필수 오류 확인. 기간 증가 시 1박 2일 표시, 당일치기 선택과 Escape 닫기 확인.
- 항공 탭 1건, 제주 검색 1건, 매거진 탭 0건 안내, 일치하지 않는 검색어의 빈 상태 및 전체 보기 6건 복구 확인. 목록 보기 선택 상태 확인.
- FAQ 예약 안내 펼치기 확인. 홈에서 브라우저 오류/경고 로그 없음.
- 실제 외부 제공자 기반 검색: 서울역→경주, 2일, 자동차로 제출. 중복 조작 방지 상태를 거쳐 `/itinerary/planme-v3-eaf37c12-1771-4572-958a-199a32316eef`로 이동하고 경주 여행 일정, 1·2일차, Standard·CarryME 시간표를 확인했다. 새 테스트 더블을 추가하거나 고정 데이터 모드를 사용하지 않았다.
- `/?q=도쿄` 목적지 초기값 유지 확인. 서울역→도쿄, 당일치기, 대중교통으로 제출하여 기존 해외 준비 안내를 확인했다.
- 서버 액션·API·DB 스키마 변경 없음. 신규 마이그레이션 없음.

## 설계 차이

미확정 사진 대신 기존 배경, 초기 일정 대신 검색 안내, 빈 매거진/뉴스레터 숨김, 확정되지 않은 할인·통계 생략은 이번 실행의 명시적 처리 방침이다. 섹션 순서와 주요 배치는 설계를 따르며, 1920×12138의 고정 높이나 예시 콘텐츠 개수를 그대로 재현하지 않는다. 모바일은 별도 원본이 없어 같은 섹션 순서로 재배치했다.
