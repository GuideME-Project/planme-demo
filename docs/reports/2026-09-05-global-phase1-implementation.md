## 초기 구현

- `apps/web/app/planme-search-actions.ts`: 기존 필수값·길이·기간·이동수단 검증과 요청 제한 뒤 국가를 확인합니다. 해외가 확인되면 V3 작업을 생성하지 않고 준비 화면 데이터를 반환합니다. 나머지는 목적지 원문으로 기존 V3 흐름을 실행합니다. 응답에 제출 식별자를 붙여 이전 오류가 새 입력에 남지 않게 했습니다.
- `apps/web/lib/planme-destination-country.ts`: 기존 `PLANME_GOOGLE_MAPS_API_KEY`를 사용한 Google Geocoding 조회입니다. 검색당 최대 1회, 제한시간 2.5초, `language=ko`, `region=kr`, 캐시 없음입니다. 모든 결과의 국가·좌표가 유효하고 부분 일치가 아니며 동일한 해외 국가를 가리키면 준비 대상으로 분기합니다. 여러 결과가 모두 KR이면 국내 원문을 유지합니다. 서로 다른 국가·KR 혼합·부분 일치·없는 입력은 미확정, 구성·조회 실패는 사용 불가로 구분합니다.
- `apps/web/components/planme-search/PlanmeGlobalPreparation.tsx`: 기존 로고 아래 밝은 파란색 안내 영역, 지구 아이콘, 목적지·국가, 준비 중/Updating 배지, 기획 문구, 6종 준비 카드를 배치했습니다. 모바일 1열·중간 화면 2열·큰 화면 3열입니다. 링크 없는 카드는 일반 정보 영역이며 가짜 버튼·상품·가격을 넣지 않았습니다. 제목 포커스는 `preventScroll`을 유지하고 페이지에만 `window.scrollTo`를 적용합니다. 안내 영역은 `overflow: clip`으로 내부 스크롤 컨테이너 생성을 방지합니다.
- `apps/web/components/planme-search/PlanmeSearchHome.tsx`: 진행 중 입력 비활성화, 중복 제출 방지, 결과 제목 포커스, 재검색 시 목적지 초기화·포커스 복원·이전 결과 제거를 적용했습니다. 출발지·기간·이동수단은 재검색 시 유지합니다.
- `apps/web/scripts/check-planme-global-country.mjs`: 실제 공급자를 호출하는 최소 검증 스크립트입니다. 테스트 더블과 가짜 공급자 응답을 사용하지 않습니다.

2번 기사 조사와 4번 제휴 조사 결과를 감독자로부터 전달받았습니다. 실기사 계약이 없어 매거진과 빈 공간을 만들지 않았고, 웹 사용 승인이 확인된 제휴 링크가 없어 6종 모두 연결 준비 중입니다. 해외 CarryME·롤러 노출 조건을 임의로 확정하지 않았습니다.

## 실제 검증

- 최종 `npm run build`: 통과. Next.js 16.2.9 컴파일·타입 검사·15개 정적 페이지 생성 완료.
- 변경한 5개 코드·검증 파일의 ESLint: 통과.
- `git diff --check`: 통과.
- `node --env-file=apps/web/.env.local apps/web/scripts/check-planme-global-country.mjs --confirm-external-api`: 후속 수정 후 재검증 통과. 부산과 Seoul은 국내 원문 유지, 도쿄는 JP, Paris는 FR, 카트만두는 NP, 나이로비는 KE, Springfield는 US로 확인했습니다. `zxqv987654321없는도시`는 미확정이며, 키 미설정은 사용 불가로 반환했습니다.
- Orca 브라우저에서 서울역→도쿄, 당일치기, 자동차를 검색해 약 0.3초에 준비 결과를 확인했습니다. 카드 6개, 카드 안 링크·버튼 0개, 결과 제목 포커스, 재검색 후 목적지 포커스와 이전 결과 제거를 확인했습니다. 1522×2019 화면의 가로 넘침은 없었습니다.
- 후속 수정 후 Orca 브라우저에서 나이로비 실제 검색이 케냐 준비 결과로 전환됐습니다. 제목 포커스와 페이지 스크롤 0을 유지했고, 안내 영역은 `overflow: clip`, `scrollTop=0`, `clientHeight=360`, `scrollHeight=452`였습니다. `scrollTop=68`을 직접 설정해도 0을 유지했습니다. 안내 영역 상단 188.5보다 목적지 배지 상단 229.5, Google Maps 상단 236.5, Updating 상단 233.5가 아래에 있어 세 표기 모두 영역 안에 있었습니다.
- 감독자 검증 수신: 회사 Chrome 390×844에서 새 도쿄 검색 후 상단 배지·6개 카드 시각 검증 통과, 안내 영역 스크롤 0, 문서 너비 375 ≤ 화면 너비 390입니다. 하단 재검색 후 이전 결과 제거, 목적지 비움·포커스 복원, 서울역·당일치기·자동차 유지도 확인했습니다.
- 감독자 데스크톱 검증 수신: 회사 Chrome 기본 데스크톱으로 복원한 뒤 새 나이로비 검색이 케냐 준비 결과로 전환됐으며, 배지·Google Maps 출처·6개 카드의 3열 배치 시각 검증이 통과했습니다.
- 브라우저 DOM에서 `requestSubmit()`을 연속 2회 실행했을 때 해당 탭의 검색 POST는 1회였습니다. 국내 검색 중 입력·기간·이동수단·검색 버튼 비활성화를 확인했습니다.
- 공백 목적지는 기존 필수 입력 안내를 표시했습니다. 없는 목적지는 해외 준비 화면으로 바뀌지 않고 기존 실패 응답을 표시했습니다.
- 부산 국내 검색은 목적지 해석, 실제 장소 180개 수집, AI 구성, 일정 배치까지 진행했으나 경로 단계에서 실패했습니다. 실제 상태 조회는 `failed / ROUTE_UNAVAILABLE`입니다. 대상 일정은 `planme-v3-edefc335-95e4-4360-8ee1-4e6db3d57758`이며 전체 국내 일정 성공으로 보고하지 않습니다.

## 제한과 자율 판단

- 단일 비부분일치 Geocoding 결과도 모든 동명 지명·오입력의 모호성을 해결하지는 않습니다. 국내 편향은 제한 조건이 아니며, 공급자 데이터의 정확성에 의존합니다.
- 판정 대상은 해외 국가이며 정확한 도시·좌표 선택이 아닙니다. 나이로비의 도시·카운티 및 Springfield의 미국 내 여러 도시처럼 모든 유효 결과가 같은 해외 국가이면 준비 대상으로 처리합니다. 국가가 다르거나 KR이 섞이면 기존 흐름을 유지합니다. 모든 해외 도시 지원이나 동명 도시 식별 완료를 주장하지 않습니다.
- 국내 원문 유지 지시를 반영해 한국어 도시로 바꾸는 정규화를 제거했습니다. 영어 국내 도시의 기존 V3 검색 지원을 확장하지 않았습니다.
- 네트워크 장애·HTTP 실패·부분 일치 응답은 코드로 분리했지만 장애를 인위적으로 주입하는 검증은 하지 않았습니다. 키 미설정 분기는 실제 환경변수 제거·복원으로 검증했습니다.
- 국내 경로 코드는 변경하지 않았습니다. 이번 부산 실패가 변경 전에도 발생했는지 동일 입력·응답의 비교 재현은 하지 않았으므로 기존 장애라고 확정하지 않습니다.
- 구현 담당의 브라우저 검증은 DOM·접근성 구조와 직접 조작 결과 기준입니다. 모바일·데스크톱 시각 검증은 위에 명시한 감독자의 독립 검증 결과를 전달받아 기록했습니다.
- 카드 색상·정보 위계·아이콘·반응형 배치는 승인된 자율 디자인 범위에서 선택했습니다. 미승인 제휴·CarryME·롤러 정책 결정은 없습니다.
- 기존 Google 설정의 추가 요청 비용은 감독자에게 확인받았습니다. 새 키·환경변수·계약·의존성 버전을 추가하지 않았습니다. 잠금 파일 기반 설치 출력에는 취약점 8건(중간 1, 높음 7)이 있었으며 자동 수정하지 않았습니다.
- PR·커밋·병합·배포를 하지 않았으며 1·2·4번 및 main 작업 공간을 수정하지 않았습니다.
