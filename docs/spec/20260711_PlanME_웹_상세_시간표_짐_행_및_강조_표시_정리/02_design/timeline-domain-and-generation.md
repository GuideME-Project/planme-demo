# 시간표 업무 의미와 생성 설계

## 결론

Standard는 짐을 놓기 위해 호텔/숙소를 중간 방문하여 체크인하는 여행자 경로다. CarryME는 여행자가 호텔 중간 방문을 생략하고, 짐만 호텔로 배송되는 경로다.

AI 지침은 Standard의 첫 호텔 방문을 `체크인`으로 명시하고, `짐 호텔 도착`을 CarryME에만 작성하도록 강화한다. AI가 지침을 어겨도 생성 후처리에서 Standard의 CarryME 배송 사건만 제거한다.

## 이유

- 현재 지침은 Standard를 `짐 때문에 호텔/숙소를 중간 방문`한다고만 설명해 `체크인 전 짐 보관` 같은 문구를 유도한다.
- `짐 숙소 도착`을 CarryME에만 넣으라는 지침은 이미 있지만 Standard와 CarryME가 같은 시간표 스키마를 사용한다.
- 현재 생성 후 정규화는 문자열을 다듬을 뿐 Standard에 CarryME 사건이 있는지 검증하지 않는다.
- 프롬프트 준수만 신뢰하면 같은 시각·장소의 여행자 도착과 짐 도착이 Standard에 함께 저장될 수 있다.

## 업무 계약

### Standard

- 첫 호텔 중간 방문은 여행자의 `호텔 체크인`이다.
- 체크인 후 관광하고 같은 호텔로 돌아오면 `호텔 복귀` 또는 `숙박`이다.
- 목적과 시간이 다른 호텔 체크인과 호텔 복귀는 모두 유지한다.
- `짐 호텔 도착`, 배송 차량 사건 등 CarryME 배송 사건은 포함하지 않는다.

### CarryME

- 여행자는 호텔 중간 체크인을 위해 경유하지 않는다.
- Standard 체크인 시각에 대응하는 `짐 호텔 도착` 사건을 표시할 수 있다.
- 짐 배송 사건은 여행자 행선지가 아니므로 CarryME 경로 stop에 추가하지 않는다.
- 호텔이 여행자의 최종 목적지이면 최종 호텔 도착은 유지한다.

## AI 생성 지침 변경

현재 `Standard 경로는 짐 때문에 호텔/숙소를 중간 방문하는 기본 경로` 지침을 다음 의미로 구체화한다.

- Standard는 짐을 놓기 위해 호텔/숙소를 중간 방문하여 체크인하는 경로다.
- Standard 첫 호텔 방문의 시간표 제목은 `{호텔명} 체크인`으로 작성한다.
- 관광 후 같은 호텔로 돌아오면 `{호텔명} 복귀` 또는 숙박 의미로 작성한다.
- Standard 시간표에는 `짐 호텔 도착`이나 CarryME 배송 사건을 작성하지 않는다.
- CarryME 시간표에만 `짐 호텔 도착`을 작성하고 사건 분류는 반드시 CarryME 분류(`category=carryme`)를 사용한다.
- Standard 시간표에서는 CarryME 분류를 사용하지 않는다.
- 호텔 체크인 가능 시간을 확인할 수 없어도 일정상 체크인으로 표현하되 통상적인 오후 시간대에 배치한다.

실제 호텔별 체크인 가능 시간 조회나 보장은 이번 범위에 포함하지 않는다.

## 생성 결과 후처리

### 판별 우선순위

1. Standard 시간표에서 CarryME 전용 분류(`category=carryme`)인 사건을 제거한다.
2. 구조화 분류가 잘못된 기존 AI 결과를 대비해 제목·설명이 짐 배송 완료를 명확히 뜻하는 사건을 보조적으로 제거한다.
3. 호텔 체크인·호텔 도착·호텔 복귀·숙박 같은 여행자 사건은 유지한다.
4. CarryME 시간표에서 짐 배송 완료 의미가 명확하지만 분류가 다르면 CarryME 분류로 정규화한다.

보조 문구 판별은 `짐/수하물`과 `배송/도착`이 결합된 배송 사건으로 제한한다. `짐 없이 바로 이동` 같은 절약 설명이나 일반 호텔 사건을 제거 조건으로 사용하지 않는다.

### 실패 처리

- Standard의 CarryME 배송 사건 하나 때문에 전체 일정을 실패시키거나 AI를 다시 호출하지 않는다.
- 해당 사건만 제거하고 나머지 일정 생성과 저장을 계속한다.
- Standard 시간표가 비어 버리는 비정상 결과는 기존 누락 검증에서 실패로 처리한다.

## 데이터 경계

- 새 일정은 생성 후처리된 Standard 시간표를 저장한다.
- 기존 저장 일정은 데이터 이관 없이 웹 호환 표시에서 보정한다.
- ChatGPT 위젯 컴포넌트의 시각 디자인은 변경하지 않는다.
- 시간표 스키마에서 `highlight`, `savingLabel`을 제거하는 계약 변경은 하지 않는다. 웹 상세 화면에서만 사용하지 않는다.

## 대안과 기각 이유

### 프롬프트만 수정

- 기각 이유: 현재도 CarryME 전용 지침을 AI가 위반한 실제 사례가 있다.

### Standard의 모든 호텔 중복 제거

- 기각 이유: 체크인과 관광 후 호텔 복귀는 목적과 시간이 다른 정상 사건이다.

### 위반 시 AI 재호출

- 기각 이유: 생성 지연과 반복 실패 가능성이 커지고, 제거 가능한 단일 사건 때문에 전체 일정을 버리게 된다.

## 리스크

- 문구 판별이 넓으면 정상 호텔 사건을 제거할 수 있다.
- 분류만 신뢰하면 잘못 분류된 과거 AI 결과를 놓칠 수 있다.
- 통상적인 오후 시간대 지침은 실제 호텔 체크인 가능 시간을 보장하지 않는다.
