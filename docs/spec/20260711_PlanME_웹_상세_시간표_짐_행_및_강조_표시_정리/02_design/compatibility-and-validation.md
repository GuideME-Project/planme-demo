# 호환성과 검증 설계

## 결론

새 일정은 생성 지침과 후처리에서 의미를 바로잡고, 기존 저장 일정은 웹 상세 표시 변환으로 호환한다. 저장 데이터 마이그레이션 없이 기존 링크와 신규 링크를 모두 개선한다.

## 호환 정책

| 대상 | 처리 | 저장 데이터 변경 |
| --- | --- | --- |
| 새 일정 Standard | 체크인 지침 적용, CarryME 배송 사건 후처리 제거 | 정규화된 결과 저장 |
| 새 일정 CarryME | 짐 배송 사건 유지 | 기존 계약 유지 |
| 기존 일정 Standard 웹 | 배송 사건 숨김, 제한된 체크인 문구 보정 | 없음 |
| 기존 일정 CarryME 웹 | 배송 사건 유지, 행 시각만 단순화 | 없음 |
| ChatGPT 위젯 시각 | 변경하지 않음 | 없음 |
| 공유 이미지 시각 | 변경하지 않음 | 없음 |

## 수용 기준

### Standard 의미

- 호텔 중간 체크인 행이 보인다.
- 관광 후 같은 호텔 도착·복귀·숙박 행이 별도 시간에 있으면 유지된다.
- 같은 시각·장소의 `짐 호텔 도착` 행은 Standard에 보이지 않는다.
- `체크인 전 짐 보관` 기존 행은 `{호텔명} 체크인`과 승인된 설명으로 보인다.

### CarryME 의미

- `짐 호텔 도착` 행이 유지된다.
- `짐 호텔 도착` 사건이 CarryME 분류와 배송 차량 아이콘으로 표시된다.
- 배송 차량 아이콘과 아이콘의 빛나는 효과가 유지된다.
- 여행자 경로 stop에 짐 배송 사건이 추가되지 않는다.

### 시각 표현

- Standard와 CarryME 일정 행에 연한 초록 배경·테두리가 없다.
- 일정 행 오른쪽 초록 체크가 없다.
- 일정 행 제목 옆 빨간 절약 칩이 없다.
- CarryME 총 이동 시간 상자와 오른쪽 빨간 절약 칩은 유지된다.
- 밝은 테마와 어두운 테마에서 동일하다.

## 자동 검증

### 생성·정규화 검증

- AI 초안 fixture의 Standard에 CarryME 분류 배송 사건을 넣고 후처리 후 제거되는지 확인한다.
- 분류가 잘못됐지만 제목·설명이 명백한 짐 배송 완료 사건도 제거되는지 확인한다.
- 호텔 체크인과 관광 후 호텔 복귀는 모두 유지되는지 확인한다.
- CarryME의 짐 배송 사건은 유지되는지 확인한다.
- CarryME 배송 의미가 명확하지만 분류가 잘못된 입력이 CarryME 분류로 정규화되는지 확인한다.

### 웹 상세 회귀 검증

- 기존 저장 일정 fixture에 Standard 여행자 호텔 도착과 같은 시각·장소의 짐 도착 사건을 함께 넣는다.
- Standard 열에는 여행자 호텔 도착만 보이고 CarryME 열에는 짐 도착이 보이는지 확인한다.
- 기존 `체크인 전 짐 보관` 제목과 설명이 승인된 체크인 문구로 보이는지 확인한다.
- 행 내부 강조 요소가 렌더링되지 않는지 안정적인 테스트 식별자나 DOM 구조로 확인한다.
- CarryME 총 이동 시간 상자의 절약 칩은 계속 보이는지 확인한다.
- 1일차·2일차 전환 후 같은 규칙이 유지되는지 확인한다.

## 수동 검증

- 기존 부산 일정 링크의 1일차·2일차를 확인한다.
- ChatGPT에서 새 부산 1박 2일 일정을 생성하고 상세 링크의 1일차·2일차를 확인한다.
- 밝은 테마와 어두운 테마에서 확인한다.
- Standard 경로와 지도에서 호텔 경유가 유지되는지 확인한다.
- 시간표의 체크인·복귀 의미와 지도 호텔 경유가 서로 모순되지 않는지 확인한다.
- ChatGPT 위젯에 시각 회귀가 없는지 확인한다.

## 실패 조건

- Standard에 `짐 호텔 도착` 또는 배송 차량 사건이 보인다.
- 정상 호텔 체크인이나 관광 후 호텔 복귀가 사라진다.
- CarryME의 짐 배송 사건이 사라진다.
- 행 내부 강조를 제거하면서 CarryME 총 이동 시간 상자의 빨간 칩까지 사라진다.
- 기존 저장 일정은 정상인데 신규 일정만 다르거나 그 반대다.
- 1일차는 정상이고 2일차 전환 후 이전 표현이 다시 나타난다.

## 롤백

- 생성 지침·후처리와 웹 표시 변환을 독립된 변경 단위로 유지한다.
- 생성 후처리에서 정상 사건이 제거되면 문구 보조 판별을 먼저 비활성화하고 구조화 분류 조건만 유지할 수 있어야 한다.
- 웹 시각 회귀가 있으면 표시 변환은 유지한 채 행 스타일 변경만 되돌릴 수 있어야 한다.
- 저장 데이터 마이그레이션이 없으므로 롤백 시 데이터 원복 작업은 필요하지 않다.

## 확인하지 못한 범위

- 전용 Linear MCP가 현재 세션에 노출되지 않아 관련 Linear 이슈·댓글 검색은 확인하지 못했다.
- 호텔별 실제 체크인 가능 시간은 외부 데이터로 확인하지 않는다.
