# PlanME 웹 상세 시간표 짐 행 및 강조 표시 정리 인터뷰

## 요약

PlanME 상세 일정의 Standard와 CarryME 시간표에 같은 강조 표현이 섞이고, Standard에 CarryME 전용 짐 배송 사건까지 노출되는 문제를 정리한다.

Standard는 짐을 놓기 위해 호텔/숙소를 중간 방문하여 체크인하는 경로다. 따라서 Standard의 호텔 체크인과 관광 후 호텔 복귀·숙박은 유지한다. 같은 시각과 장소의 `짐 호텔 도착`은 CarryME 전용 배송 사건이므로 Standard에서 제거하고 CarryME에만 표시한다.

웹 상세 화면에서는 Standard와 CarryME 일정 행의 초록 배경·체크·행 내부 빨간 절약 칩을 제거한다. CarryME의 짐 배송 행과 배송 아이콘은 유지하며, CarryME 총 이동 시간 상자의 빨간 절약 칩도 유지한다.

## 확정사항

- Standard 경로는 짐을 놓기 위해 호텔/숙소를 중간 방문하여 체크인하는 경로다.
- Standard의 첫 호텔 중간 방문은 `호텔 체크인`으로 표현한다.
- 관광 후 같은 호텔에 다시 도착하면 `호텔 복귀` 또는 `숙박`으로 표현할 수 있다.
- 13시 호텔 중간 방문과 18시 관광 후 호텔 도착처럼 목적과 시간이 다른 두 호텔 사건은 정상이다.
- 같은 시각·같은 장소에 여행자 호텔 도착과 `짐 호텔 도착`이 Standard에 함께 표시되는 것은 오류다.
- Standard에는 `짐 호텔 도착`과 CarryME 배송 사건을 작성하거나 표시하지 않는다.
- CarryME에는 `짐 호텔 도착` 배송 사건을 유지한다.
- AI가 Standard에 CarryME 배송 사건을 작성하면 후처리에서 제거한다.
- 체크인 가능 시간이 확인되지 않아도 `호텔 체크인`으로 표시하되 AI가 통상적인 오후 시간대에 배치하도록 지침을 보강한다.
- 실제 호텔 체크인 가능 시간을 외부 데이터로 검증하는 기능은 이번 범위에서 제외한다.
- 기존 저장 일정의 `체크인 전 짐 보관`은 웹 상세 화면에서 `{호텔명} 체크인`으로 표시한다.
- 기존 저장 일정의 해당 설명은 `호텔에 체크인한 뒤 다음 일정으로 이동합니다.`로 함께 보정한다.
- 웹 상세 화면의 Standard와 CarryME 일정 행에서 연한 초록 배경·테두리, 초록 체크, 행 내부 빨간 절약 칩을 제거한다.
- CarryME 짐 배송 행의 배송 차량 아이콘과 빛나는 효과는 유지한다.
- CarryME 총 이동 시간 상자와 상자 오른쪽의 빨간 절약 칩은 유지한다.
- 시각 변경은 웹 상세 화면의 밝은 테마와 어두운 테마에 적용한다.
- 기존 저장 일정과 새로 생성하는 일정 모두를 검증한다.

## 범위 구분

- 새 일정: AI 생성 지침과 생성 결과 후처리를 보강한다.
- 기존 일정: 저장 데이터를 이관하지 않고 웹 상세 화면에서 호환 표시를 적용한다.
- 시각 표현: 웹 상세 화면만 변경한다.
- ChatGPT 위젯과 공유 이미지 컴포넌트의 시각 디자인은 변경하지 않는다.

## 관련 결정과 차이

- 기존 `CarryME 일정 경로 버그` 문서는 Standard가 호텔을 경유하고 CarryME 여행자는 호텔 중간 방문을 생략한다는 경로 의미를 정의한다.
- 이번 결정은 그 경로 차이를 유지하면서 Standard 호텔 사건을 `짐 보관`이 아닌 `체크인`으로 명확하게 표현한다.
- 기존 문서를 덮어쓰지 않고 별도 문서로 남겨 변경된 표현 정책과 적용 범위를 구분한다.

## 다음 설계 액션

- AI 지침에서 Standard 첫 호텔 방문을 체크인으로 명시하고 CarryME 배송 사건 금지를 강화한다.
- Standard의 CarryME 배송 사건만 제거하는 결정적 후처리 기준을 설계한다.
- 기존 저장 일정의 제한된 체크인 문구 보정과 Standard 배송 사건 제거를 웹 표시 계층에 설계한다.
- 기존 부산 일정과 새 일정의 1일차·2일차 및 두 테마를 검증하는 회귀 테스트를 설계한다.
