# 기존 일정 호환과 검증 범위

## 목적

- 이 주제를 확인하는 이유: 기존 저장 일정에는 `체크인 전 짐 보관`과 Standard에 섞인 CarryME 배송 사건이 이미 존재할 수 있으며, 새 생성 지침만 고치면 현재 공유 링크가 개선되지 않는다.
- 이 주제가 불명확하면 생기는 리스크: 생성 시점에 따라 같은 웹 화면이 서로 다른 의미를 보여주거나, 웹 시각 변경이 ChatGPT 위젯까지 불필요하게 확대될 수 있다.

## Questions

1. 기존 저장 일정과 새 일정에 각각 어떤 보정을 적용할 것인가?
2. ChatGPT 위젯과 공유 이미지의 시각 디자인도 변경할 것인가?
3. 어떤 일정과 일차를 검증할 것인가?
4. 자동 회귀 테스트를 추가할 것인가?

## Answers

1. 새 일정에는 AI 지침과 생성 후처리를 적용하고, 기존 일정에는 저장 데이터 이관 없이 웹 표시 호환 보정을 적용한다.
2. 웹 상세 화면의 시각 디자인만 변경한다.
3. 기존 부산 일정과 새로 생성한 일정의 1일차·2일차를 확인한다.
4. 같은 문제가 다시 생기지 않도록 화면 회귀 테스트를 추가한다.

## Score

- 현재 불명확성 점수: `0.07`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 신규·기존 데이터의 처리 경계, 시각 비목표, 대표 수동·자동 검증 범위가 확정됐다.
- 다음에 낮춰야 할 불확실성: 실제 기존 일정에서 제한된 문구 보정과 배송 사건 제거가 기대대로 동작하는지 구현 검증이 필요하다.

## Confirmed

- 새 일정의 Standard 생성 지침은 호텔 체크인 의미를 명확히 한다.
- 새 일정의 Standard에 CarryME 배송 사건이 들어오면 후처리에서 제거한다.
- 기존 저장 데이터는 직접 수정하거나 이관하지 않는다.
- 기존 웹 상세 화면에서는 `체크인 전 짐 보관`의 제목·설명을 제한적으로 보정하고 Standard의 CarryME 배송 사건을 숨긴다.
- ChatGPT 위젯과 공유 이미지 컴포넌트의 시각 디자인은 변경하지 않는다.
- 밝은 테마와 어두운 테마를 모두 검증한다.
- 기존 부산 일정과 새 일정의 1일차·2일차를 확인한다.
- Standard의 호텔 체크인·복귀는 유지되고 CarryME 배송 사건만 제거되는지 확인한다.
- 양쪽 일정 행에서 초록 배경·체크·행 내부 빨간 칩이 사라졌는지 확인한다.
- CarryME 총 이동 시간 상자의 빨간 칩이 유지되는지 확인한다.
- 자동 화면 회귀 테스트를 추가한다.

## Open Questions

- 없음. 구현 결과의 화면 자연스러움은 수동 검증에서 확인한다.
