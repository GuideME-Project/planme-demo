재발 방지를 위해 다음 계약을 로컬에서 검증했다.

- GPTs와 GuideME 앱의 공개 도구 입력에서 모델이 채울 수 있는 별도 `transportMode` 필드를 제거한다.
- 서버는 최신 사용자 원문 `latestUserMessage`에서 자동차 또는 대중교통 한 가지가 명시된 경우에만 내부 이동 수단을 파생한다.
- 이동 수단이 없는 실제 회귀 입력에 구 GPTs 스키마의 `transportMode: drive`가 함께 와도 `needs_clarification`을 반환하고 일정 ID를 만들지 않는다.
- 구 GPTs 스키마가 `latestUserMessage`를 보내지 않아도 생성하지 않고 같은 이동 수단 질문을 반환한다.
- 사용자 원문과 구 구조화 값이 충돌하면 사용자 원문을 우선하며, 새 OpenAPI와 앱 도구 스키마에는 구조화 이동 수단 필드를 노출하지 않는다.
- `자동차요`, `대중교통이요`, `대중교통을 이용할게`는 선택으로 인정하고, `자동차 없이 여행`, `자동차를 선택 안 할게요`, `대중교통을 이용 안 해요`, `자동차 박물관에서 출발`, 두 수단 동시 언급은 선택으로 인정하지 않는다.
- 이동 수단이 없거나 두 수단을 함께 말한 입력은 실제 생성 실행기를 0회 호출하고, 사용자 원문 `대중교통`과 구 구조화 값 `drive`가 충돌한 입력만 `transit`으로 정확히 1회 호출한다.
- 최신 사용자 원문은 내부 일정 생성·저장 입력에서 제거하고, 이동 수단 질문은 장소 미확정 목록을 오염시키지 않는다.
