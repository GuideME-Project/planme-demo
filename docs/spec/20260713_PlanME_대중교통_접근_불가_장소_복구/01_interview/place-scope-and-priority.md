# 장소 고정 범위와 우선순위

## 목적

- 이 주제를 확인하는 이유: 사용자가 지정한 여행 범위와 장소를 보존하면서 접근 불가능한 AI 추천 장소만 안전하게 바꿔야 한다.
- 이 주제가 불명확하면 생기는 리스크: `남해` 같은 지역명이 `남해군청` 같은 임의 방문지로 변하거나, 사용자가 반드시 가려던 장소가 자동 교체될 수 있다.

## Questions

1. 사용자가 지역 또는 정확한 장소명을 말했을 때 무엇을 고정해야 하는가?
2. 넓은 지역명을 일정 정류장 또는 방문지로 삽입해야 하는가?
3. 접근성이 낮은 장소를 AI가 골랐을 때 중간 경로와 방문지를 바꿔도 되는가?
4. 이번 복구 정책을 자동차 일정에도 적용해야 하는가?
5. 요구사항 입력을 위한 별도 UI 변경이 필요한가?

## Answers

1. 출발지는 고정한다. 넓은 지역명은 여행 범위로 고정하고, 사용자가 직접 말한 정확한 장소는 필수 방문지로 고정한다.
2. 넓은 지역명 자체를 방문지로 만들지 않는다. AI는 해당 지역 안에서 실제 방문 장소를 선택한다.
3. 목적지가 사용자가 말한 곳과 같거나 같은 지역 범위 안에 있으면 중간 경로와 AI 추천 장소는 바꿔도 된다.
4. 이번 문제는 대중교통 일정에만 해당한다. 자동차 일정은 현재 정상 동작하므로 변경하지 않는다.
5. 사용자는 보통 첫 한두 번의 프롬프트에서 목적지나 지역을 말하므로 별도 UI 변경은 필요하지 않다.

## Score

- 현재 불명확성 점수: `0.10`
- 목표 임계값: Standard `0.20`
- 점수 근거: 출발지, 지역, 사용자 지정 장소, AI 추천 장소의 보존 우선순위와 대중교통 한정 범위가 확정됐다.
- 다음에 낮춰야 할 불확실성: 자연어에서 지역과 정확한 장소를 구분하는 기술 규칙은 설계 단계에서 기존 장소 구조를 기준으로 정한다.

## Confirmed

- 출발지(`origin`)는 고정한다.
- 여행 지역(`region`)은 선택 범위로 고정하되 방문지 목록에 임의 삽입하지 않는다.
- 사용자 지정 장소(`mustVisitPlaces`)는 고정한다.
- AI 추천 장소는 같은 지역 범위 안에서 교체할 수 있다.
- 대중교통(`transit`)에만 적용하고 자동차(`drive`)는 기존 동작을 보존한다.
- 별도 UI를 추가하지 않는다.
