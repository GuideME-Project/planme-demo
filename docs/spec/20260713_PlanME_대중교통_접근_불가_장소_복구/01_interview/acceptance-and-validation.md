# 수락 기준과 검증 시나리오

## 목적

- 이 주제를 확인하는 이유: 실제 실패가 발생한 GPTs와 GPT 앱을 같은 조건으로 검증하고, 정상인 자동차 일정의 회귀를 막아야 한다.
- 이 주제가 불명확하면 생기는 리스크: 내부 모의 테스트만 통과하고 실제 ChatGPT 새 대화에서는 다시 422가 발생하거나, 대중교통 수정이 자동차 경로에 영향을 줄 수 있다.

## Questions

1. 어떤 ChatGPT 표면에서 검증해야 하는가?
2. 대중교통 대표 시나리오는 무엇인가?
3. 정상 동작 중인 자동차 경로도 검증해야 하는가?
4. 생성 성공 외에 어떤 결과를 확인해야 하는가?

## Answers

1. 새 대화에서 맞춤형 GPT의 PlanME와 일반 ChatGPT의 GuideME-PlanME 앱을 각각 호출한다.
2. `강동역 출발 → 남해 1박 2일, 대중교통`을 기본 시나리오로 사용하고, 남해독일마을·보리암처럼 정류장 접근성이 다른 장소를 포함해 검증한다.
3. `동탄호수공원 출발 → 부산 1박 2일, 자동차` 시나리오로 자동차 경로가 바뀌지 않았는지 확인한다.
4. 422 미발생, 사용자 지정 장소 유지, AI 장소 교체 상한, 도보시간 반영, 시간표 보정, 저장 링크와 최종화 상태를 함께 확인한다.

## Score

- 현재 불명확성 점수: `0.15`
- 목표 임계값: Standard `0.20`
- 점수 근거: 실제 제품 표면, 대표 대중교통·자동차 시나리오와 핵심 통과 조건이 확정됐다.
- 다음에 낮춰야 할 불확실성: 구현 계획에서 모의 응답과 실제 ODsay 호출의 분리, 호출량과 로그 조회 절차를 구체화한다.

## Confirmed

- GPTs와 GPT 앱은 반드시 각각 새 대화에서 검증한다.
- GPTs에서는 PlanME를 호출한다.
- 일반 ChatGPT에서는 GuideME-PlanME 앱을 호출한다.
- 대중교통 기본 시나리오는 `강동역 → 남해 1박 2일`이다.
- 사용자 지정 장소가 있는 시나리오와 AI가 장소를 선택하는 지역 단위 시나리오를 모두 확인한다.
- 결과 링크가 열리고 허용 기준 안의 일정은 `routeFinalized=true`여야 한다.
- 실제 또는 추정 도보시간이 전체 이동시간과 이후 시간표에 반영돼야 한다.
- 추정 구간이 있으면 절약시간이 숨겨져야 한다.
- 자동차 기본 시나리오는 `동탄호수공원 → 부산 1박 2일`이며 기존 동작을 유지해야 한다.

## Open Questions

- 실제 ODsay 호출 검증에 필요한 예상 호출량과 운영 키 사용 범위는 구현 계획 전에 정한다.
- 사용자 지정 장소의 편도 추정 도보가 90분을 초과하는 실제 ChatGPT 응답 형식은 설계 단계에서 정한다.
- 산악 보행 경로의 정답 비교 기준으로 ODsay 응답 외에 어떤 수동 근거를 사용할지 정한다.

## Acceptance Criteria

1. GPTs PlanME와 GuideME-PlanME 앱 모두 일정 생성 API에서 422를 반환하지 않는다.
2. 사용자가 지정한 지역과 장소가 보존된다.
3. 접근 불가능한 AI 추천 장소는 같은 지역의 후보를 최대 세 곳까지 확인한 뒤 교체 또는 제거된다.
4. 사용자 지정 장소는 자동 교체되지 않는다.
5. ODsay 실제 도보 경로 또는 승인된 보수적 추정시간이 이동시간 합계에 포함된다.
6. 이후 시간표는 계산된 이동시간에 맞게 보정되며 순서와 날짜 경계를 위반하지 않는다.
7. 추정 구간은 실제 경로선으로 표시되지 않고 절약시간도 노출하지 않는다.
8. 허용 기준 안의 결과 링크가 정상적으로 열리고 `routeFinalized=true`로 저장된다.
9. 자동차 일정의 네이버 경로 계산과 상세 화면이 기존과 동일하게 동작한다.
10. 실패 로그에는 공급자, 내부 코드, 일차, 경로, 구간 번호와 AI 생성 장소가 남고 사용자 출발지는 남지 않는다.
