## 핵심 확정사항

- 이번 변경 대상은 대중교통(`transit`) 일정뿐이며 자동차(`drive`) 경로는 변경하지 않는다.
- 출발지는 고정하고, 사용자가 말한 지역은 일정 범위로 고정하되 그 지역명을 임의의 방문지로 바꾸지 않는다.
- 사용자가 직접 지정한 장소는 고정하고 AI가 추천한 장소만 대중교통 접근성에 따라 교체할 수 있다.
- 목적지 정류장이 없으면 주변 정류장을 찾고, 정류장까지 대중교통 경로와 정류장에서 목적지까지 도보 경로를 분리해 계산한다.
- AI 추천 장소는 실제 도보 30분 이내일 때 유지하고, 초과하거나 도보 경로가 없으면 최대 세 후보까지 교체한다.
- 사용자 지정 장소는 자동 교체하지 않는다. 실제 도보 경로가 없으면 보수적으로 시간을 추정하며, 편도 90분 이하는 자동 최종화할 수 있다.
- AI 교체 후보 세 곳이 모두 실패하면 해당 장소만 제거해 여유시간으로 처리한다. 하루의 모든 방문지가 제거될 때만 일정 생성을 중단한다.
- 추정 구간을 포함해도 허용 기준 안이면 경로 최종화 완료(`routeFinalized=true`)로 저장한다.
- 추정 구간은 내부적으로 `estimated`로 구분하고 경로선을 만들지 않는다.
- Standard·CarryME 중 하나라도 추정 구간을 포함하면 절약시간을 숨기며, 별도의 `경로 계산 불가` 문구는 추가하지 않는다.
- 경로 최종화 시 계산된 이동시간을 이후 시간표에도 반영하되 일정 순서와 날짜 경계를 깨뜨리지 않는다.
- 별도 UI 변경은 요구하지 않는다.

## 현재 확인한 근거

- 운영 실패 로그에서 ODsay 오류 코드 `4`인 `도착지 정류장이 없습니다`가 일정 저장 API의 422로 이어졌다.
- 같은 ChatGPT 표면이라도 AI가 선택한 장소 조합에 따라 생성 성공과 실패가 달라졌다.
- ODsay는 반경 내 대중교통 POI 검색과 별도 도보 길찾기 API를 제공한다.
- ODsay 도보 길찾기는 직선거리 30km 이내로 제한되며, 보행 도로망 연결 실패나 경로 없음으로 더 짧은 거리에서도 실패할 수 있다.
- 현재 서버 경로 최종화는 700m 이하 구간을 실제 도보 경로 없이 직선거리와 4km/h로 추정한다.
- 현재 서버 경로 최종화는 AI 시간표 배열을 변경하지 않는 검증을 두고 있어, 확정된 시간표 보정 요구사항과 충돌한다.

## 설계 단계로 넘길 기술 확인사항

- 현재 ODsay 계약에서 전용 도보 길찾기를 운영 호출할 수 있는지 서면 또는 계정 기준으로 확인한다.
- 반경 내 정류장 검색의 지원 최대 반경과 호출 비용을 실제 키 또는 공급자 답변으로 확인한다.
- 도보 실패 시 적용할 우회계수, 보행속도, 여유시간의 정확한 값을 대표 사례로 검증한다.
- 시간표 보정이 날짜 경계를 넘거나 장소 운영시간과 충돌할 때의 처리 계약을 설계한다.
- 신규 `estimated` 상태가 저장 DTO, 상세 화면, GPTs 응답과 GPT 앱 응답에서 손실되지 않도록 데이터 계약을 정한다.
