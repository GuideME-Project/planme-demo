# 정류장 및 도보 복구

## 목적

ODsay가 목적지 정류장을 자동 선택하지 못하는 대중교통 구간을 더 먼 정류장과 마지막 도보로 복구한다. 실제로 걸을 수 없는 구간을 직선 경로선으로 위장하지 않으면서 일정 이동시간을 완성한다.

## 적용 조건

- 일정 이동수단이 `transit`일 때만 적용한다.
- ODsay 대중교통 오류 코드 `4`인 `도착지 정류장이 없습니다`에만 주변 정류장 복구를 시작한다.
- `drive`는 네이버 자동차 경로의 기존 처리를 유지한다.
- 700m 이하 짧은 대중교통 구간의 기존 추정 정책은 별도 회귀 대상으로 유지하되, 저장 상태는 신규 `durationSource` 계약을 따른다.

## 복구 알고리즘

### 1. 주변 정류장 탐색

1. ODsay `pointSearch`로 목적지 좌표 주변의 버스정류장·지하철역·기차역·터미널을 조회한다.
2. 검색 반경은 작은 값부터 단계적으로 확대한다.
3. 공식 문서로 확인되지 않은 최대 반경을 코드에 임의 상수로 넣지 않는다.
4. 기능 활성화 전에 운영 키로 지원 최대 반경을 측정하고 설정값 `ODSay station search maximum radius`로 제한한다.
5. 거리와 대중교통 시설 유형을 기준으로 중복 정류장을 제거한 뒤 최대 세 후보만 경로 평가 대상으로 남긴다.

### 2. 후보별 경로 평가

각 후보에 대해 다음 두 구간을 독립적으로 계산한다.

1. 이전 일정 장소에서 후보 정류장까지 ODsay 대중교통 경로
2. 후보 정류장에서 원래 목적지까지 ODsay 전용 도보 경로

대중교통 경로가 없으면 해당 후보를 제외한다. 도보 API가 성공하면 공급자 시간과 실제 경로선을 사용한다. 도보 API가 실패하면 아래 추정 규칙을 적용하되 실제 경로선을 생성하지 않는다.

### 3. 보수적 도보시간 추정

```text
estimatedDistanceMeters = straightLineDistanceMeters × 1.5
estimatedWalkMinutes =
  ceil(estimatedDistanceMeters / 3.5km/h) + 5분
```

- 계산 결과는 분 단위로 올림한다.
- 5분은 보행 도로 진입, 횡단과 위치 오차를 위한 고정 여유시간이다.
- 추정 경로의 `geometryStatus`는 부분 또는 없음으로 유지한다.
- 지도에 직선 연결선을 실제 도보 경로처럼 추가하지 않는다.
- 직선거리만으로도 해당 장소의 허용시간을 명백히 넘는 후보는 도보 API 호출 전에 제외할 수 있다.

### 4. 후보 선택

`대중교통 시간 + 마지막 도보시간`이 가장 짧은 후보를 선택한다.

동률이면 다음 순서를 적용한다.

1. 실제 도보시간인 후보
2. 도보시간이 더 짧은 후보
3. 목적지 직선거리가 더 가까운 후보
4. 공급자 결과 순서가 앞선 후보

## 장소 유형별 허용 기준

| 장소 유형 | 유지 기준 | 초과 또는 실패 시 |
| --- | --- | --- |
| AI 추천 장소(`replaceable`) | 실제 또는 추정 마지막 도보가 편도 30분 이하 | 웹이 장소 교체 필요를 MCP에 반환 |
| 사용자 고정 장소(`fixed`) | 실제 또는 추정 마지막 도보가 편도 90분 이하 | 자동 최종화하지 않고 사용자 확인 요청 |

- 사용자 고정 장소는 자동 교체하거나 제거하지 않는다.
- 정류장 자체를 찾지 못하면 AI 장소는 교체 대상으로, 사용자 고정 장소는 확인 대상으로 전환한다.
- 사용자 고정 장소가 90분 이하이면 추정 구간이 있어도 `routeFinalized=true`가 될 수 있다.

## 결과 데이터

`RouteProviderSegment`에 출처를 추가한다.

```ts
type RouteProviderSegment = {
  durationSeconds: number;
  durationSource: "provider" | "estimated";
  geometryStatus: "full" | "partial" | "none";
  // 기존 필드 생략
};
```

복구된 구간은 대중교통 부분과 마지막 도보 부분의 시간을 합산한다. 실제 도보 형상이 있으면 공급자 경로에 연결하고, 추정이면 대중교통 경로까지만 유지한다.

## 공급자 오류 처리

| 상황 | 처리 |
| --- | --- |
| 대중교통 오류 코드 `4` | 주변 정류장 복구 시작 |
| 도보 요청 직선거리 30km 초과 | 도보 API를 호출하지 않고 허용시간 사전 필터 적용 |
| 도보 오류 `411`, `412`, `413`, `414` | 보수적 추정으로 전환 |
| 주변 검색 또는 공급자 일시 오류 | 제한된 재시도 후 동일한 장소 유형별 실패 흐름 적용 |
| 인증·계약 오류 | 추정으로 조용히 덮지 않고 운영 오류로 기록하고 요청 실패 |

인증·계약 오류는 장소 접근성 문제가 아니므로 AI 장소를 반복 교체하지 않는다.

## 호출 예산

- 장소 한 곳당 정류장 후보 경로 평가는 최대 세 건이다.
- 같은 좌표 쌍과 이동수단의 성공 결과는 요청 추적 범위에서 재사용한다.
- 후보 탐색과 경로 계산을 무제한 병렬 실행하지 않는다.
- 개별 웹 경로 계산은 기존 40초 상한을 넘기지 않고, MCP 사전검사와 최종 저장은 더 짧은 전역 시간 예산을 함께 사용한다.

## 검증 기준

1. 오류 코드 `4`가 발생해도 적합한 정류장과 도보가 있으면 일정 저장이 성공한다.
2. 후보가 여러 개면 전체 이동시간이 가장 짧은 후보를 선택한다.
3. AI 장소의 마지막 도보 30분 초과는 장소 교체 요청으로 전환한다.
4. 사용자 고정 장소의 마지막 도보 90분 이하는 실제·추정 여부와 관계없이 유지한다.
5. 추정 구간은 시간에는 포함되지만 실제 경로선은 생성하지 않는다.
6. 자동차 경로 제공자는 이 알고리즘을 호출하지 않는다.

## 외부 확인 필요

- ODsay 운영 계약에서 `searchWalkPathV2`를 서버 호출로 사용할 수 있는지 확인한다.
- `pointSearch`가 운영 키에서 허용하는 최대 반경과 호출 비용을 확인한다.
- 남해 보리암처럼 산악 목적지에서 추정식이 과소 추정하지 않는지 실제 공급자·지도 결과와 비교한다.
