# 로그 관측·검증 기준

## 목적

- 이 주제를 확인하는 이유: 맞춤형 GPT의 응답 크기와 GPT 앱의 상세 저장 실패 단계를 운영 로그에서 식별한다.
- 이 주제가 불명확하면 생기는 리스크: 서버 응답과 ChatGPT 오류를 연결하지 못하고, 상세 저장 422가 다시 발생해도 실제 실패 단계를 구분할 수 없다.

## Questions

1. 맞춤형 GPT 응답에서 어떤 측정값을 기록하는가?
2. 상세 저장 실패를 진단하기 위해 무엇을 기록하는가?
3. 민감정보 보호를 위해 무엇을 기록하지 않는가?
4. 서로 다른 서버의 로그를 어떻게 연결하는가?

## Answers

1. HTTP 200 응답의 UTF-8 JSON 바이트 수와 HTTP 상태를 기록한다. 응답 본문은 기록하지 않는다.
2. 실패 단계, 안전한 내부 오류 코드, 외부 경로 제공자, 일차, 경로 종류, 구간 번호, 재시도 여부를 기록한다. 경로 제공자 실패 구간의 방문지·숙소는 장소명과 좌표도 기록한다.
3. 사용자 출발지와 같은 장소인 복귀지의 장소명·좌표, 일정 원문, 요청·응답 본문, 인증정보와 환경변수는 기록하지 않는다.
4. 요청마다 UUID 추적 식별자를 만들고 MCP에서 웹 상세 저장 API까지 전달한다.

## Score

- 현재 불명확성 점수: `0.10`
- 목표 임계값: `Quick 0.30`
- 점수 근거: 응답 크기 측정값, 추적 식별자, 운영 로그의 허용·금지 정보가 확정됐다.
- 다음에 낮춰야 할 불확실성: 설계 단계에서 구체적인 오류 코드 목록과 자동 테스트 계층을 정한다.

## Confirmed

- 맞춤형 GPT 성공 응답의 바이트 수를 본문 없이 기록한다.
- 운영 로그는 일정 내용 없이 실패 단계를 구분할 수 있어야 한다.
- MCP와 웹 로그는 같은 추적 식별자로 연결할 수 있어야 한다.
- 외부 오류 원문 대신 내부 표준 오류 코드만 기록한다.
- 사용자 출발지·복귀지는 숨기고 AI가 생성한 방문지·숙소와 구간 번호는 경로 실패 로그에 기록한다.

## Open Questions
