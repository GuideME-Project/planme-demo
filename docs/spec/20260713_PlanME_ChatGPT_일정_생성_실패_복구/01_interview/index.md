# PlanME ChatGPT 일정 생성 실패 로그 개선 인터뷰

## 문서 정보

- 한글 주제명: PlanME ChatGPT 일정 생성 실패 로그 개선
- Linear 이슈: 없음
- 인터뷰 깊이: Quick (`0.30` 이하)
- 인터뷰 종료 사유: 사용자가 인터뷰 문서 작성을 요청함

## 핵심 확정사항

- 맞춤형 GPT 요청과 GPT 앱 요청을 각각 추적할 수 있어야 한다.
- MCP에서 웹 상세 저장 API까지 같은 추적 식별자를 전달한다.
- 맞춤형 GPT 성공 응답의 UTF-8 JSON 바이트 수를 기록한다.
- 경로 제공자 실패 로그에는 구간 번호와 AI가 생성한 방문지·숙소의 장소명·좌표를 기록한다.
- 사용자 출발지와 같은 장소인 복귀지는 장소명·좌표를 기록하지 않는다.
- 일정 원문, 인증정보와 외부 제공자 응답 원문은 기록하지 않는다.
- 실제 실패 사례는 추적 식별자로 MCP와 웹 로그를 연결해 확인한다.

## 현재 확인한 근거

- 맞춤형 GPT의 일정 추천 API는 운영 환경에서 200을 반환했지만 ChatGPT 대화에는 응답 용량 오류가 표시됐다.
- GPT 앱은 일정 생성 후 상세 일정 저장을 두 차례 시도했으며, 두 요청 모두 상세 저장 API에서 422를 반환했다.
- 현재 상세 저장 API의 422 응답은 경로 최종화 실패를 뜻하지만 운영 로그에는 세부 실패 코드가 남지 않는다.

## 미결정사항

- 확인된 422가 좌표 검색, ODsay 인증, 경로 없음, 외부 요청 실패 중 어느 세부 원인인지는 기존 로그만으로 구분할 수 없다.
