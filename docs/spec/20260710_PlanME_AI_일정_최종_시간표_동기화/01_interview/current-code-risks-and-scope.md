# 현재 코드 리스크와 미결정사항

## 목적

- 이 주제를 확인하는 이유: 기존 단일 경로 시간 필드를 길찾기의 순수 이동 시간으로 일관되게 사용하는 방법과 서버 계산 전환 범위를 기록한다.
- 이 주제가 불명확하면 생기는 리스크: 저장된 AI 예상 이동 시간과 길찾기 이동 시간이 같은 필드에 섞여 화면마다 다른 값이 나올 수 있다.

## Questions

1. 현재 경로 소요 시간 필드를 계속 사용할 수 있는가?
2. 체류 시간이나 방문 시각을 새로 계산하는가?
3. 기존 생성 일정도 새 기준으로 계산할 것인가?
4. 긴급 배포에서 ChatGPT 위젯 동기화를 제외할 수 있는가?

## Answers

1. 사용할 수 있다. 최종 저장 이후 `durationMinutes`와 `durationLabel`은 네이버 또는 대중교통 제공자가 계산한 순수 이동 시간만 의미하도록 고정한다. AI 예상 이동 시간은 최종 저장값으로 사용하지 않는다.
2. 계산하지 않는다. 기존 AI 장소 순서와 시간표 내용은 유지하고, 이동 시간과 지도 경로만 길찾기 결과로 확정한다.
3. 기존 상세 일정 링크는 최초 접근 시 새 기준으로 한 번 계산해 저장한다. 과거 ChatGPT 위젯은 소급 갱신하지 않는다.
4. 제외하지 않는다. 긴급 배포에서도 ChatGPT 위젯과 상세 웹이 동일한 이동 시간과 경로를 보여주는 범위를 유지한다.

## Score

- 현재 불명확성 점수: `0.25`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 제품 기준과 기존 상세 링크 처리는 확정됐지만 저장 버전, 대중교통 성공 판정과 검증 범위가 남아 있다.
- 다음에 낮춰야 할 불확실성: 설계 단계에서 저장 버전과 대중교통 성공 판정을 확정해야 한다.

## Confirmed

- 체류 시간이나 전체 일정 소요 시간 필드를 추가하지 않는다.
- 기존 경로 소요 시간은 최종 저장 이후 순수 이동 시간만 의미한다.
- 현재 브라우저 중심 재계산을 서버 중심 최종 계산과 저장 방식으로 변경한다.
- 녹화 일정이 급해도 위젯과 웹의 이동 시간·지도 경로 일치는 범위에서 제외하지 않는다.

## Open Questions

- 계산 상태와 최종 결과를 현재 저장소에 어떻게 버전 관리할지 미결정이다.
- 자동차·대중교통별 전체 성공 판정과 부분 지도 경로 허용 기준이 미결정이다.
- 위젯·웹·새로고침·일차 전환·편집 실패를 포함한 최종 검증 시나리오가 미결정이다.
