# TourAPI와 AI 책임 경계

## 목적

- 이 주제를 확인하는 이유: 장소 사실과 일정 판단의 권한을 분리해 AI의 장소 발명과 좌표 조작을 구조적으로 막는다.
- 이 주제가 불명확하면 생기는 리스크: 프롬프트 위반이나 모델 교체만으로 존재하지 않는 장소, 이름, 좌표가 일정에 저장될 수 있다.

## Questions

1. 목적지 장소의 유일한 원천은 무엇인가?
2. TourAPI 호출을 AI 도구 호출로 맡길 것인가, 서버가 먼저 수행할 것인가?
3. AI가 생성할 수 있는 데이터의 범위는 어디까지인가?
4. 사용할 모델과 추론 강도, 실패 시 대체 정책은 무엇인가?
5. 좌표가 없거나 잘못된 TourAPI 장소는 어떻게 처리하는가?
6. 선택된 TourAPI 장소는 일정에 어떤 형태로 저장하는가?
7. TourAPI 단일 원천 규칙은 출발지·목적지 경로 기준점에도 적용하는가?
8. 축소 일정도 생성할 수 있는 최소 TourAPI 후보 조건은 무엇인가?
9. 여행 기간보다 실제 방문 장소 후보가 적으면 어떻게 처리하는가?

## Answers

1. TourAPI를 관광지, 문화시설, 레포츠, 쇼핑, 숙소, 음식점의 유일한 장소 원천으로 사용한다.
2. PlanME 서버 함수가 TourAPI를 먼저 호출하고 정규화된 후보 스냅샷을 AI에 전달한다. AI가 TourAPI를 직접 호출하지 않는다.
3. AI는 후보에 포함된 `contentId`의 선택, 방문 순서, 일차 배분만 반환한다. 장소 이름·좌표·새 장소·시간표는 생성하지 않는다.
4. `gpt-5.6-luna`와 낮은 추론 강도(`low`)를 사용한다. 같은 모델을 한 번 재시도하고, 실패하면 서버의 결정적 대체 로직을 사용한다. 다른 모델로 자동 전환하지 않는다.
5. `mapX`, `mapY`가 누락됐거나 0, 숫자 아님, 허용 범위 밖이면 AI 전달 전에 후보에서 제외한다. AI나 지오코더로 좌표를 추측하지 않는다.
6. 각 일정 revision에 선택 당시의 최소 정규화 장소 스냅샷을 저장한다. `contentId`, 콘텐츠 유형, 공식 장소명, 좌표, 주소, 필요한 표시 필드와 출처 시각만 포함하고 TourAPI 전체 원본 응답은 저장하지 않는다.
7. 일정 장소에는 TourAPI만 사용한다. 임의 주소·역 이름일 수 있는 출발지와 목적지 경로 기준점은 기존 네이버 지오코딩으로 확인할 수 있지만 관광 장소 후보로 승격하지 않는다.
8. TourAPI 숙소 후보 1개 이상과 숙소·음식점을 제외한 실제 방문 장소 1개 이상이 있어야 한다. 음식점은 없어도 생성할 수 있다.
9. 요청한 여행 기간은 유지하되 같은 `contentId`를 일정 채우기용으로 반복하지 않는다. 장소가 부족한 시간은 위치 없는 자유시간 또는 숙소 휴식으로 채운다.

- 다음에 낮춰야 할 불확실성: AI 입력 후보 수 상한과 결정적 대체 정렬식을 설계 단계에서 정한다.

## Confirmed

- 프롬프트에 장소 발명 금지를 명시하되 프롬프트만 신뢰하지 않는다.
- 서버는 AI가 반환한 모든 `contentId`가 전달한 후보 허용 목록에 포함되는지 검증한다.
- AI가 반환한 이름과 좌표는 수용하지 않으며 최종 표시값은 TourAPI 스냅샷에서 다시 결합한다.
- 일정에 사용할 콘텐츠 유형은 관광지, 문화시설, 레포츠, 쇼핑, 숙소, 음식점이다.
- 여행코스처럼 여러 장소가 합쳐진 콘텐츠는 제외한다.
- 행사·축제는 실제 여행 날짜가 있을 때만 포함한다.
- 숙소는 TourAPI 숙박 후보 중 하나를 AI가 고른다.
- 음식점이 없으면 위치 없는 일반 식사 시간을 서버가 넣으며, 이를 장소로 취급하지 않는다.
- 기존 일정 화면은 TourAPI를 다시 조회하지 않고 해당 revision에 저장된 장소 스냅샷을 사용한다.
- 새 revision은 자신이 계산에 사용한 정확한 장소 스냅샷을 함께 저장한다.
- 콘텐츠 유형별 장애 시에만 최대 7일의 마지막 정상 캐시를 사용할 수 있으며 정상적인 빈 응답에는 적용하지 않는다.
- 출발지·목적지 지오코딩 결과는 경로 시작·종료 기준점으로만 사용한다.
- AI는 사용자가 지정한 출발지·목적지 이름과 서버가 확인한 좌표를 변경할 수 없다.
- 출발지 또는 목적지 좌표 확인이 실패한 경우에만 해당 값을 사용자에게 다시 질문할 수 있다.
- 숙소 후보가 없거나 실제 방문 장소가 하나도 없으면 장소를 발명하지 않고 생성 실패로 처리한다.
- 음식점 후보가 없으면 위치 없는 일반 식사 시간으로 대체한다.
- 장소 수가 부족해도 AI가 새 장소를 만들거나 기존 TourAPI 장소를 복제하지 않는다.
- 첫날 도착 이동과 마지막 날 복귀 이동은 장소 수와 무관하게 유지한다.
