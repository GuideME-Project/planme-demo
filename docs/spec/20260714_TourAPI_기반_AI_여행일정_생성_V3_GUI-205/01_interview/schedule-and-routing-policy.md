# 일정과 경로 보정 정책

## 목적

- 이 주제를 확인하는 이유: AI가 아니라 서버 계산 결과가 최종 시간표와 경로의 기준이 되도록 고정한다.
- 이 주제가 불명확하면 생기는 리스크: AI 방문 시각과 실제 ODsay·네이버 이동시간이 충돌하거나, 근거리 대중교통 오류가 전체 일정 실패로 번질 수 있다.

## Questions

1. 체류시간, 식사, 숙소 복귀와 최종 시간표는 누가 계산하는가?
2. 기본 일과 시간은 어떻게 정하는가?
3. ODsay가 근거리 경로를 반환하지 않거나 도보 경로까지 실패하면 어떻게 하는가?
4. 그 밖의 ODsay 오류는 어떻게 분류하는가?
5. `estimated_walk`의 고정 보행속도와 시간 반올림 기준은 무엇인가?

## Answers

1. PlanME 서버가 체류시간, 실제 이동시간, 식사, 숙소와 수하물 규칙, 최종 시간표를 계산한다.
2. 첫날은 목적지까지 실제 이동이 끝난 뒤 시작한다. 중간 날은 숙소에서 09:30에 출발한다. 마지막 날은 09:30에 출발하고 17:00 복귀 이동을 시작한다. 점심은 12:00~14:00, 저녁은 18:00~20:00 범위에 배치한다.
3. 대중교통 `-98`이고 두 장소가 700m 이내면 ODsay 도보 API를 시도한다. 도보 API가 411~414로 실패하면 직선거리와 고정 보행속도로 시간을 추정하고 지도 경로선은 표시하지 않으며 `estimated_walk`로 저장한다.
4. 오류 코드별로 재시도, 장소 제외, 일정 축소, 입력 실패, 인증 실패를 구분한다. 알 수 없는 오류는 성공으로 간주하지 않는다.
5. 시속 4km를 사용해 `직선거리 ÷ 보행속도`로 계산하고 분 단위로 올림한다. 최소 1분이며 700m를 초과하면 적용하지 않는다.

## Score

- 현재 불명확성 점수: `0.14`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 일정 기본값, 핵심 ODsay 보정과 예상 도보 계산 상수가 확정됐다. 세부 오류 상태 전이와 전체 성공 조건은 설계가 필요하다.
- 다음에 낮춰야 할 불확실성: 오류 코드별 상태 전이, 장소 제외 후 재계산 한도와 전체 성공 조건을 정한다.

## Confirmed

- 일정 생성 시 선호 시간은 사용자에게 질문하지 않는다.
- 여행 전체에서 숙소 하나를 사용하고 매일 숙소 복귀를 서버가 삽입한다.
- 음식점이 있으면 서버가 점심·저녁 시간대에 배치한다.
- 음식점 후보가 없으면 위치 없는 식사 시간으로 계속 생성한다.
- 방문 장소가 부족한 시간대는 위치 없는 자유시간 또는 숙소 휴식으로 구성한다.
- `estimated_walk`는 실제 도보 경로가 아니므로 지도 경로선을 만들지 않는다.
- `estimated_walk`는 시속 4km, 분 단위 올림, 최소 1분으로 계산한다.
- `estimated_walk`는 700m 이하에서만 허용하고 데이터와 화면에서 예상값으로 구분한다.
- ODsay 3·4·5는 정류장 없음 계열로 장소 제외 또는 일정 축소를 검토한다.
- ODsay 6은 서비스 지역 밖, `-99`는 경로 없음으로 해당 장소를 제외한다.
- ODsay `-8`·`-9` 입력 오류와 인증 오류는 생성 실패로 처리한다.
- 429, 타임아웃, 500, `-1` 같은 일시 오류만 제한적으로 재시도한다.
- 문서화되지 않은 오류는 실패 폐쇄 방식으로 처리한다.

## Open Questions

- 한 장소 제외 후 같은 일차를 재계산할 최대 횟수와 최소 장소 수가 미정이다.
- 자동차 경로 제공자 오류를 ODsay와 같은 상태 모델로 통일할지 미정이다.
