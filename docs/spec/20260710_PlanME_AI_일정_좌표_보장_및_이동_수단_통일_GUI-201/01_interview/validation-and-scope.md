# 완료 검증과 범위

## 목적

- 이 주제를 확인하는 이유: 좌표 검색, AI 교체, 전체 이동 수단, 실제 길안내 중 일부만 동작해도 완료로 오판하지 않도록 검증 기준을 고정해야 한다.
- 이 주제가 불명확하면 생기는 리스크: 모의 응답만 통과하고 실제 네이버 검색이나 지도 경로선이 실패하거나 기존 데이터 호환까지 범위가 불필요하게 확장될 수 있다.

## Questions

1. 대표 실제 검증 시나리오는 무엇인가?
2. 자동차와 대중교통을 실제 화면에서 비교해야 하는가?
3. 기본 경로(Standard)와 CarryME 경로 중 어디까지 실제 검증해야 하는가?
4. 실제 네이버 외부 API를 호출해야 하는가?
5. 실제 ODsay 대중교통 검증도 이번 범위인가?
6. 기존 일정 링크와 저장 데이터를 지원해야 하는가?
7. AI의 중간 행선지 교체·제외 사실을 사용자에게 보여줄 것인가?
8. Linear GUI-201을 수정할 것인가?

## Answers

1. 대표 시나리오는 `동탄 출발 → 경주월드 방문 → 동탄 복귀, 1박 2일, 자동차`다.
2. 자동차와 대중교통을 동시에 보여주거나 품질 비교하지 않는다. 대표 실제 화면 검증은 자동차로 진행한다.
3. 기본 경로(Standard)와 CarryME 경로 모두 좌표, 네이버 자동차 길안내, 네이버 지도 실제 경로선이 정상이어야 완료다.
4. 모의 응답 테스트뿐 아니라 실제 네이버 지역 검색과 실제 네이버 자동차 길안내 호출 후 화면까지 확인한다.
5. 대중교통은 전체 이동 수단 값 전달과 모든 대표 구간 통일을 모의 응답 테스트로 검증한다. 실제 ODsay 호출과 경로 품질 검증은 후속으로 남긴다.
6. 기존 일정 링크, 저장 데이터, 행선지별 이동 수단을 새 전체 이동 수단으로 변환하는 작업은 제외한다. 새로 생성되는 일정만 대상으로 한다.
7. 사용자에게는 좌표가 확인된 최종 일정만 보여주고 내부 교체·제외 과정은 노출하지 않는다. 내부 기록은 원래 장소명, 시도 횟수, 유지·교체·제외 상태 정도로 제한하고 인증 정보와 전체 외부 API 응답은 남기지 않는다.
8. GUI-201은 관련 이슈로 연결만 하고 제목, 본문, 상태, 코멘트를 수정하지 않는다.

## Score

- 현재 불명확성 점수: `0.10`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 대표 시나리오, 실제 외부 검증, 두 비교 경로, 대중교통 검증 수준, 기존 데이터 제외, 사용자 노출, Linear 비변경이 확정됐다.
- 다음에 낮춰야 할 불확실성: 실제 외부 API 검증의 예상 호출량과 실행 환경은 구현 계획에서 확인한다.

## Confirmed

- 실제 검증 전 네이버 지역 검색 인증 정보가 현재 worktree에 안전하게 준비되어야 한다.
- 실제 외부 API 호출 전 인증 정보의 존재만 확인하고 값을 출력하지 않는다.
- 자동차 대표 시나리오에서 기본 경로와 CarryME 경로가 모두 성공해야 한다.
- 실제 공급자 경로선이 없으면 성공으로 판정하지 않는다.
- 대중교통은 모의 응답 기반 계약 검증까지만 포함한다.
- 기존 링크와 저장 데이터 호환은 비목표다.
- Google Places 제거 후 국내 네이버 단일 검색 흐름을 검증한다.
- Linear GUI-201은 변경하지 않는다.

## Non-goals

- 기존 일정 링크 마이그레이션
- 기존 행선지별 이동 수단 데이터 변환
- 해외 장소 검색
- Google Places 보조 검색
- 실제 ODsay 대중교통 호출과 경로 품질 검증
- 자동차와 대중교통의 동시 비교 화면
- Linear 이슈 수정

## Open Questions

- 실제 네이버 지역 검색과 자동차 길안내의 호출량과 비용은 구현 계획에서 산정한다.
- 실제 화면 검증의 로컬 포트와 브라우저 크기는 구현 계획에서 정한다.
