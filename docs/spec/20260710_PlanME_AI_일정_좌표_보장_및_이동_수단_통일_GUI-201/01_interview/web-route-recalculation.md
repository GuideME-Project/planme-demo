# 웹 경로 재계산과 오류 표시

## 목적

- 이 주제를 확인하는 이유: 사용자가 웹에서 행선지나 전체 이동 수단을 바꾼 뒤 언제 외부 길안내를 호출하고 어떤 결과를 표시할지 고정해야 한다.
- 이 주제가 불명확하면 생기는 리스크: 입력할 때마다 외부 API가 호출되거나 좌표 없는 행선지로 경로 계산을 시도하거나 실패한 직선을 실제 경로처럼 표시할 수 있다.

## Questions

1. 웹에서 이동 수단을 행선지별로 바꿀 수 있는가?
2. 전체 이동 수단을 웹에서 다시 변경할 수 있는가?
3. 이동 수단을 바꾸면 언제 경로를 다시 계산할 것인가?
4. 사용자가 행선지명만 수정하고 장소를 선택하지 않은 상태에서 어떻게 처리할 것인가?
5. 기본 경로(Standard)나 CarryME 경로 중 한쪽만 실패하면 어떻게 표시할 것인가?
6. 현재 Google 자동완성의 오사카 중심 설정을 어떻게 볼 것인가?

## Answers

1. 행선지별 이동 수단 선택기는 제거하고 일정 전체 이동 수단 하나만 둔다.
2. 사용자는 웹에서 자동차와 대중교통 사이의 전체 이동 수단을 다시 변경할 수 있다.
3. 이동 수단을 바꾸는 것만으로 외부 API를 호출하지 않는다. 사용자가 경로 재계산 버튼을 눌렀을 때 기본 경로와 CarryME 경로를 함께 다시 계산한다.
4. 행선지명을 직접 수정하면 기존 좌표와 검색 출처를 무효화한다. 장소를 다시 선택하기 전에는 경로 재계산을 막고 `장소를 선택해 주세요`라고 안내한다.
5. 성공한 경로는 유지하고 실패한 경로에만 `경로를 확인하지 못했습니다`라고 표시한다. 직선이나 추정 경로선을 그리지 않고 실패를 성공 상태로 표시하지 않는다.
6. 오사카 반경 50km로 고정된 현재 Google 자동완성 설정은 국내 1차 범위에 맞지 않는 버그다. 웹 장소 검색을 네이버 지역 검색으로 교체하면서 제거한다.

## Score

- 현재 불명확성 점수: `0.10`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 전체 이동 수단 변경, 명시적 재계산, 좌표 없는 편집 상태, 부분 실패, 직선 대체 금지, 오사카 설정 처리가 확정됐다.
- 다음에 낮춰야 할 불확실성: 전체 이동 수단 선택기와 경로 재계산 버튼의 정확한 화면 위치는 설계 단계에서 정한다.

## Confirmed

- 웹에는 일정 전체 이동 수단 선택기 하나만 둔다.
- 자동차와 대중교통 결과를 동시에 비교하지 않는다.
- 기본 경로(Standard)와 CarryME 경로 비교 구조는 유지하고 두 경로에 같은 전체 이동 수단을 적용한다.
- 이동 수단 변경 후 사용자가 버튼을 눌러야 경로를 다시 계산한다.
- 장소 선택 없이 이름만 바꾼 행선지는 경로 계산에 사용할 수 없다.
- 장소 선택 안내에는 검색 공급자 이름을 표시하지 않는다.
- 한쪽 경로 실패가 다른 쪽 성공 결과를 지우지 않는다.
- 직선이나 추정 경로선으로 실패를 숨기지 않는다.
- 기존에 만들어진 일정 링크와 행선지별 이동 수단 데이터는 호환 대상에서 제외한다.

## Open Questions

- 전체 이동 수단 변경 시 기존 경로 결과를 즉시 흐리거나 버튼 실행 전까지 유지할지 설계 단계에서 정한다.
- 좌표 없는 행선지의 강조 방식과 경로 재계산 버튼 비활성화 표현은 화면 설계에서 정한다.
