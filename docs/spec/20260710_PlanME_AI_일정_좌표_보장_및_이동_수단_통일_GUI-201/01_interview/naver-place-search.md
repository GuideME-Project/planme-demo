# 네이버 단일 장소 검색

## 목적

- 이 주제를 확인하는 이유: 국내 장소 검색과 네이버 지도·자동차 길안내에 사용할 좌표를 하나의 공급자 기준으로 맞춰야 한다.
- 이 주제가 불명확하면 생기는 리스크: Google Places와 네이버 결과의 장소명·좌표·식별 방식이 달라 좌표 누락과 잘못된 후보 선택이 반복될 수 있다.

## Questions

1. AI 일정 생성과 웹 행선지 편집에서 어떤 장소 검색 공급자를 사용할 것인가?
2. 네이버 지역 검색과 Google Places를 함께 사용할 것인가?
3. 중심 좌표·반경 기반 주변 장소 검색이 필요한가?
4. 웹 입력 중 네이버 지역 검색은 언제 호출할 것인가?
5. 장소 검색 공급자 이름을 사용자 안내에 표시할 것인가?
6. 네이버 지역 검색 인증 정보는 어디에 있는가?

## Answers

1. AI 일정 생성과 웹 행선지 편집 모두 네이버 지역 검색만 사용한다.
2. Google Places는 보조 검색으로도 사용하지 않는다. 자동완성, 상세 조회, 텍스트 검색, 주변 검색을 새 일정 생성 흐름에서 사용하지 않는다.
3. 중심 좌표·반경 검색은 사용하지 않는다. AI가 지역명과 장소 종류를 포함한 텍스트 검색어를 작성하고, 적절한 후보가 없으면 검색어를 바꿔 최대 2회 다시 찾는다.
4. 웹에서는 두 글자 이상 입력하고 약 300ms 동안 추가 입력이 없을 때 검색한다. 새 입력이 들어오면 이전 요청을 취소한다.
5. 사용자에게 검색 공급자를 노출하지 않는다. 좌표 없는 웹 행선지에는 `장소를 선택해 주세요`라고 안내한다.
6. 네이버 지역 검색 API 인증 정보는 원본 체크아웃의 `.env`에 있다. 현재 worktree에는 인터뷰 종료 후 별도 절차로 복사하며 값은 출력하지 않는다.

## Score

- 현재 불명확성 점수: `0.10`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 단일 공급자, Google Places 제외, 텍스트 검색만 사용, 웹 호출 조건, 사용자 문구, 인증 정보 위치가 확정됐다.
- 다음에 낮춰야 할 불확실성: 네이버 결과에 Google 장소 식별자와 같은 고유 값이 없을 때 사용할 검색 출처 식별값 구조를 설계해야 한다.

## Confirmed

- 1차 지원 범위는 대한민국 국내 장소다.
- 네이버 지역 검색 결과의 장소명, 주소, 좌표를 장소 후보로 사용한다.
- AI 내부 장소 검색과 웹 편집 검색 모두 네이버만 사용한다.
- Google Places로 자동 전환하지 않는다.
- 네이버 주소 좌표 변환만으로 상호명을 찾으려 하지 않고 네이버 지역 검색을 장소 검색의 중심으로 사용한다.
- 네이버의 중심 좌표·반경 검색 기능을 별도로 요구하지 않는다.
- 웹 검색은 두 글자 이상, 약 300ms 입력 지연 기준을 사용한다.
- 사용자 문구에는 네이버라는 공급자 이름을 넣지 않는다.
