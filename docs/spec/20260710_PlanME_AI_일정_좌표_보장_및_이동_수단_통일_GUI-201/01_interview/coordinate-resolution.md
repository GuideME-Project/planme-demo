# 좌표 보장과 AI 행선지 교체

## 목적

- 이 주제를 확인하는 이유: 네이버 자동차 길안내, ODsay 대중교통 길안내, 네이버 지도 경로선은 행선지 좌표가 있어야 계산할 수 있다.
- 이 주제가 불명확하면 생기는 리스크: 좌표가 없는 장소가 최종 일정에 포함되어 길안내가 중단되거나 임의 경로선이 실제 경로처럼 보일 수 있다.

## Questions

1. 좌표를 반드시 보장해야 하는 장소는 어디까지인가?
2. 사용자 지정 출발지나 목적지를 찾지 못하면 어떻게 처리할 것인가?
3. `동탄`처럼 넓은 지역명이 출발지이면 대표 좌표를 자동 선택할 것인가?
4. AI가 만든 중간 행선지에 좌표가 없으면 누가 교체할 것인가?
5. 중간 행선지의 대체 장소를 몇 번까지 찾고, 모두 실패하면 어떻게 처리할 것인가?
6. 사용자 지정 목적지는 일정의 마지막 행선지로 고정할 것인가?
7. 복귀지는 어떻게 결정할 것인가?

## Answers

1. 최종 일정에 포함되는 출발지, 방문지, 숙소, 복귀지는 모두 좌표를 가져야 한다. 좌표 없는 중간 행선지는 최종 일정에 남기지 않는다.
2. 출발지와 사용자 지정 목적지는 AI가 임의로 바꾸지 않는다. 네이버 검색으로도 찾지 못하면 일정과 상세 링크를 만들지 않고 정확한 장소명이나 주소를 다시 묻는다.
3. 넓은 출발 지역은 네이버 검색 결과에서 대표 좌표를 자동 선택한다. 대표 좌표도 찾지 못할 때만 사용자에게 다시 묻는다.
4. AI가 만든 중간 행선지의 좌표를 확인하지 못하면 AI가 같은 지역, 일정 주제, 장소 종류를 최대한 유지하는 다른 실제 장소로 자동 교체한다. 사용자 확인은 다시 받지 않는다.
5. 좌표 없는 중간 행선지 하나당 대체 검색은 최대 2회다. 두 번 모두 실패하면 해당 행선지를 제외하고 출발지·목적지·나머지 유효 행선지로 일정을 계속 생성한다.
6. 사용자 지정 목적지는 반드시 일정에 포함하되 방문 날짜와 순서는 AI가 정할 수 있다. 전체 일정의 마지막 행선지로 강제하지 않는다.
7. 사용자가 편도나 별도 최종 도착지를 명시하지 않으면 출발지를 복귀지로 사용한다. 당일과 여러 날 일정에 같은 기준을 적용한다.

## Score

- 현재 불명확성 점수: `0.10`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 필수 좌표 대상, 출발지·목적지 실패, 중간 행선지 교체·제외, 대표 좌표, 목적지 순서, 복귀지 정책이 확정됐다.
- 다음에 낮춰야 할 불확실성: 넓은 지역의 대표 좌표를 선택하는 구체 알고리즘은 설계 단계에서 정한다.

## Confirmed

- AI나 코드가 좌표를 추측하지 않는다.
- 최종 일정에 남는 모든 행선지는 좌표와 검색 출처를 가진다.
- 출발지와 사용자 지정 목적지는 필수이며 AI가 교체할 수 없다.
- 중간 행선지만 AI가 최대 2회 교체할 수 있다.
- 두 번 실패한 중간 행선지는 제외하며 전체 일정 생성을 막지 않는다.
- 출발지나 목적지를 찾지 못하면 사용자에게 더 정확한 장소명이나 주소를 요청한다.
- 넓은 출발 지역은 대표 좌표를 자동 선택한다.
- 사용자 지정 목적지는 일정에 반드시 포함하되 방문 순서는 AI가 정한다.
- 기본 복귀지는 출발지다.

## Open Questions

- 행정구역, 역, 상권처럼 유형이 다른 넓은 지역의 대표 좌표 선택 우선순위는 설계 단계에서 정한다.
- 동일한 장소명이 여러 지역에 있을 때 네이버 후보를 구분하는 내부 점수 기준은 설계 단계에서 정한다.
