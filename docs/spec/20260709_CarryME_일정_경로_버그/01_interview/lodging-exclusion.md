# 호텔/숙소 판단과 여행자 경로 제외 기준

## 목적

- 이 주제를 확인하는 이유: AI 일정 초안에서 호텔/숙소가 여행자 CarryME 경로에 중간 경유지로 섞이면 의도와 달라진다.
- 이 주제가 불명확하면 생기는 리스크: CarryME 경로가 "짐 없이 바로 관광하는 경로"가 아니라 "호텔/숙소를 들렀다 가는 경로"처럼 계산될 수 있다.

## Questions

1. AI가 행선지 검색 중 숙소 정보도 검색하는가?
2. 호텔/숙소에 짐을 맡기기 위해 사람이 들르는 루트는 제외하고 CarryME 여행자 경로로 다시 볼 수 있는가?
3. 호텔/숙소 판단은 코드가 하는가, AI가 하는가?
4. 호텔/숙소를 CarryME 여행자 경로에서 어떻게 다룰 것인가?

## Answers

1. 코드 확인 결과, 사용자가 숙소를 직접 주지 않으면 Google Places로 숙소 후보를 검색한다.
2. 가능하다. API 자체 문제가 아니라 CarryME 계산용 정류장 목록에서 호텔/숙소 중간 경유를 빼느냐의 문제다.
3. 호텔/숙소 판단은 AI가 1차로 맡는다. 코드는 호텔/숙소 키워드로 적극 추론하지 않는다.
4. 호텔/숙소가 중간 경유지이면 CarryME 여행자 경로에서 제외한다. 여행의 마지막 목적지가 호텔/숙소라면 최종 목적지로 유지한다.

## Score

- 현재 불명확성 점수: `0.08`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 판단 주체, 제외 기준, 레거시 역할값 처리 방향이 답변으로 확정됐다.
- 다음에 낮춰야 할 불확실성: AI가 호텔/숙소를 안정적으로 구조화하도록 하는 프롬프트/스키마 표현.

## Confirmed

- 사용자 의미의 중심은 호텔/숙소다.
- 요구사항과 화면 문구에서 별도 배송 목적지 개념을 중심에 두지 않는다.
- 호텔/숙소는 짐이 가는 곳이다.
- CarryME 여행자 경로는 호텔/숙소 중간 경유 없이 바로 관광지/최종 목적지로 간다.
- 호텔/숙소가 여행의 최종 목적지이면 CarryME 여행자 경로에 유지한다.
- AI가 호텔/숙소를 문맥으로 판단한다.
- 코드가 `호텔`, `숙소`, `hotel`, `resort` 같은 키워드로 적극 판단하는 방식은 피한다.
- 기존 레거시 역할값은 구현에서 무시한다.

## Open Questions
