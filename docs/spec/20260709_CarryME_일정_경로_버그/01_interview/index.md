## 요약

CarryME 일정 버그의 핵심은 "CarryME 경로"가 짐 배송 경로인지, 여행자가 짐 없이 이동하는 경로인지 화면에서 섞여 보이는 문제다.

인터뷰에서 확정된 방향은 CarryME 경로를 여행자 CarryME 경로, 즉 호텔/숙소를 먼저 들르지 않고 바로 관광지/최종 목적지로 이동하는 길로 보는 것이다.

호텔/숙소는 짐이 가는 곳이다. Standard 일정에서 사람이 호텔/숙소에 도착하던 시간은 CarryME 일정에서는 `짐 숙소 도착` 이벤트 시간으로 재사용한다.

## 확정사항

- 지도 범례/안내의 CarryME 여행자 경로 이름은 `짐 없이 바로 이동하는 경로`다.
- 절약 시간이 있으면 `약 N분 절약`을 쓴다.
- 절약 시간이 없으면 `시간 절약 없음 · 짐 없이 바로 이동`을 쓴다.
- 적용 범위는 상세 화면, GPT/ChatGPT용 일정 미리보기 이미지, GPT Action API 응답이다.
- 기존 Redis preview 저장값은 직접 수정하지 않는다.
- 짐 배송 차량 경로 점선 표시는 이번 범위에서 제외한다.
- 호텔/숙소 판단은 AI가 1차로 맡는다. 코드는 호텔/숙소 키워드로 적극 추론하지 않는다.
- 기존 레거시 역할값은 구현에서 무시한다.
- CarryME 여행자 경로에서는 호텔/숙소 중간 경유를 뺀다.
- CarryME 경로는 Standard에서 호텔/숙소 중간 방문을 제거한 뒤 다시 계산한다.
- CarryME 경로 재계산이 실패하면 별도 오류로 보이지 않게 하고, CarryME 경로/시간을 Standard와 동일하게 표시한다.
- CarryME 타임라인에는 Standard에서 호텔/숙소에 도착하던 시간에 `짐 숙소 도착` 이벤트를 표시한다.
- 행선지 편집은 단순 방문지 목록이 아니라 일자별 전체 이동 흐름 편집이다.
- 행선지 편집에는 `출발지`, `방문지`, `숙소`, `복귀지`가 모두 들어간다.
- 1일차 출발지는 사용자가 처음 입력한 전체 여행 출발지다.
- 마지막 날 복귀지는 사용자가 처음 입력한 전체 여행 출발지다.
- 2일차 이상 출발 기준은 AI 명시값을 우선하고, 누락 시 전날 마지막 숙소 이벤트/숙소 지점을 사용한다.
- 숙소는 행선지 편집에서 항상 `숙소`로 표시한다.
- AI가 각 행선지 stop에 역할을 내려주고, 코드는 index나 이름으로 적극 추론하지 않는다.
- AI가 제안한 장소에 좌표가 없으면 기존 장소 검색/상세 조회 흐름을 사용해 좌표를 확정한다.
- 좌표가 없는 행선지는 provider path/polyline과 소요시간 계산 전에 차단한다.
- 대표 검증 시나리오는 시간 절약이 없는 시나리오다.
- 대표 검증 입력은 실제 Custom GPT/MCP 흐름으로 생성한 일정 하나를 사용한다.
