# 구현 재적용 후보

## 목적

- 이 주제를 확인하는 이유: 원본 워크트리가 삭제되어 실제 패치가 남아 있지 않으므로, 대화와 코드 근거만으로 재적용 범위를 복구해야 한다.
- 이 주제가 불명확하면 생기는 리스크: 인터뷰에서 확정되지 않은 범위까지 구현하거나, 반대로 핵심 버그를 놓칠 수 있다.

## Questions

1. 사라진 작업에서 구현으로 다시 가져와야 할 항목은 무엇인가?
2. 구현에서 제외해야 할 항목은 무엇인가?
3. 구현 후 어떤 기준으로 확인할 것인가?

## Answers

1. 호텔/숙소 중간 경유를 CarryME 여행자 경로에서 제거하고, CarryME 경로만 다시 계산한다. 문구, 지도 범례, GPT 응답/미리보기 이미지도 같은 기준으로 맞춘다.
2. 짐 배송 차량 점선 경로 표시, 기존 Redis preview 저장값 직접 수정, 레거시 역할값 기반 판단, 코드 키워드 기반 호텔/숙소 적극 추론은 제외한다.
3. 실제 Custom GPT/MCP 흐름으로 생성한 일정 하나를 대표 입력으로 사용하고, 시간 절약이 없는 시나리오가 `시간 절약 없음 · 짐 없이 바로 이동`으로 보이는지 확인한다.

## Score

- 현재 불명확성 점수: `0.12`
- 목표 임계값: `Standard 0.20`
- 점수 근거: 재적용 항목, 제외 항목, 대표 검증 입력이 확정됐다.
- 다음에 낮춰야 할 불확실성: 설계 단계에서 각 항목을 어떤 함수/컴포넌트 경계에 배치할지.

## Confirmed

- AI 일정 생성 프롬프트에는 여행자 CarryME 경로 규칙을 반영한다.
- AI가 호텔/숙소를 문맥으로 판단한다.
- 호텔/숙소는 짐이 가는 곳이지만, CarryME 여행자 경로의 중간 경유지로 넣지 않는다.
- 호텔/숙소가 여행자가 실제 도착해야 하는 최종 목적지라면 유지한다.
- 기존 레거시 역할값은 구현 기준으로 사용하지 않는다.
- GPT 초안 후처리에서는 AI가 호텔/숙소로 정리한 중간 경유지를 CarryME 여행자 경로에서 제외한다.
- 절약 없음 문구는 `시간 절약 없음 · 짐 없이 바로 이동`으로 바꾼다.
- 절약 있음 문구는 `약 N분 절약`을 유지한다.
- 지도 범례 문구는 `짐 없이 바로 이동하는 경로`로 바꾼다.
- 지도 말풍선은 문자열 비교보다 실제 절약 시간이 1분 이상인지 여부로 분기한다.
- CarryME 타임라인에는 Standard 일정에서 사람이 호텔/숙소에 도착하던 시간을 재사용해 `짐 숙소 도착` 이벤트를 보여준다.
- 별도 배송 예상 도착 시간 계산, 고정 시간, 외부 배송 연동은 하지 않는다.
- Standard 일정은 기본 기준으로 둔다.
- CarryME 경로만 Standard에서 호텔/숙소 중간 방문을 제거한 뒤 다시 계산한다.
- 절약 시간은 `Standard 총 이동 시간 - CarryME 재계산 총 이동 시간`으로 계산한다.
- CarryME 재계산 실패 시 CarryME 경로/시간은 Standard와 동일하게 표시하고, 별도 오류로 노출하지 않는다.
- 기존 `planme:preview:*` 저장값은 직접 수정하지 않는다.
- 새로 생성되는 일정, 상세 화면 표시, GPT/ChatGPT용 일정 미리보기 이미지, GPT Action API 응답부터 새 기준을 적용한다.

- 설계 단계에서 각 구현 항목의 책임 파일과 함수 경계를 정해야 한다.

## Suggested Verification

- 시간 절약이 없는 대표 시나리오에서 문구가 `시간 절약 없음 · 짐 없이 바로 이동`으로 표시되는지 확인한다.
- 지도 범례가 `짐 없이 바로 이동하는 경로`로 표시되는지 확인한다.
- Standard 일정의 호텔/숙소 도착 시간이 CarryME 타임라인의 `짐 숙소 도착` 시간으로 재사용되는지 확인한다.
- CarryME 여행자 경로에서 호텔/숙소 중간 경유가 빠지는지 확인한다.
- CarryME 경로가 호텔/숙소 중간 방문 제거 후 다시 계산되는지 확인한다.
- CarryME 재계산 실패 시 CarryME 경로/시간이 Standard와 동일하게 표시되고 별도 오류가 노출되지 않는지 확인한다.
- 최종 목적지가 호텔/숙소인 일정에서는 CarryME 여행자 경로 마지막 목적지가 사라지지 않는지 확인한다.
- Standard 총 이동 시간이 CarryME 총 이동 시간보다 작거나 같을 때 문구가 `시간 절약 없음 · 짐 없이 바로 이동`으로 표시되는지 확인한다.
- 절약 시간이 있을 때 기존 `약 N분 절약` 문구가 유지되는지 확인한다.
- 대표 검증 입력은 실제 Custom GPT/MCP 흐름으로 생성한 일정 하나를 사용한다.
