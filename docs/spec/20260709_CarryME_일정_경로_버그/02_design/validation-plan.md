# 검증 계획

## 결론

검증은 실제 Custom GPT/MCP 흐름으로 생성한 일정 하나를 대표 입력으로 삼는다.
대표 시나리오는 시간 절약이 없는 경우이며, 이때도 화면과 GPT 응답은 `시간 절약 없음 · 짐 없이 바로 이동`을 일관되게 보여줘야 한다.
검증 대상은 호텔/숙소를 코드로 판별하는 능력이 아니라, AI 생성 결과와 확정된 표시 규칙이 이어지는지다.

## 검증 대상

| 대상 | 확인 내용 |
| --- | --- |
| 상세 화면 | CarryME 경로가 `짐 없이 바로 이동하는 경로`로 표시되는지 확인한다. |
| 행선지 편집 | `출발지`, `방문지`, `숙소`, `복귀지` role이 index가 아니라 데이터 role대로 표시되는지 확인한다. |
| 경로 재계산 | Standard는 기준으로 유지하고 CarryME만 재계산되는지 확인한다. |
| 좌표 방어 | 좌표 없는 행선지는 기존 장소 검색/상세 조회 흐름으로 확정 전까지 경로 계산이 차단되는지 확인한다. |
| 실패 fallback | CarryME 재계산 실패 시 오류 대신 Standard와 같은 경로/시간을 보여주는지 확인한다. |
| 타임라인 | Standard 호텔/숙소 도착 시간을 CarryME의 `짐 숙소 도착` 이벤트 시간으로 사용하는지 확인한다. |
| GPT Action 응답 | `savedMinutes`, 총 이동 시간, 요약 문구가 화면과 같은 의미인지 확인한다. |
| 미리보기 이미지 | GPT/ChatGPT 공유 이미지에 절약/절약 없음 문구가 같은 기준으로 표시되는지 확인한다. |
| 저장값 | 기존 Redis preview 저장값을 직접 수정하지 않는지 확인한다. |

## 대표 시나리오

- 실제 Custom GPT/MCP 흐름으로 새 일정을 생성한다.
- Standard 일정에는 호텔/숙소 중간 방문이 존재한다.
- CarryME 일정은 호텔/숙소 중간 방문 없이 바로 이동하는 여행자 경로로 표시된다.
- 행선지 편집에는 첫 출발지, 현지 방문지, 숙소, 마지막 날 복귀지가 모두 표시된다.
- 1박 일정과 2박 이상 일정에서 일자별 출발 기준이 올바르게 표시된다.
- CarryME 재계산 결과가 Standard보다 짧지 않으면 `시간 절약 없음 · 짐 없이 바로 이동`을 표시한다.

## 실패 시나리오

CarryME 경로 재계산이 실패하면 화면 전면 오류로 처리하지 않는다.
Standard와 같은 경로/시간을 CarryME에도 표시하고, 절약 시간은 0으로 처리한다.
사용자는 실패를 해결해야 하는 상태로 몰리지 않고, 짐 없이 이동한다는 의미만 유지해서 본다.

## 수동 검증 체크리스트

- 상세 화면 상단 절약 문구가 조건에 맞는지 확인한다.
- 지도 범례에 `짐 없이 바로 이동하는 경로`가 보이는지 확인한다.
- 행선지 편집 첫 row가 실제 `출발지` role일 때만 출발지로 보이는지 확인한다.
- 첫 방문지가 `출발지`로 오표시되지 않는지 확인한다.
- 숙소 row가 마지막에 있어도 `숙소`로 표시되는지 확인한다.
- 마지막 날 처음 출발지로 돌아가는 row가 `복귀지`로 표시되는지 확인한다.
- 좌표 없는 행선지가 있으면 기존 장소 검색/상세 조회로 좌표를 확정하기 전까지 재계산이 막히는지 확인한다.
- CarryME timeline에 `짐 숙소 도착`이 보이는지 확인한다.
- GPT Action 응답의 `summary`와 `savedMinutes`가 화면과 맞는지 확인한다.
- GPT/ChatGPT 미리보기 이미지의 절약 문구가 상세 화면과 맞는지 확인한다.
- 기존 Redis preview 데이터를 직접 migration하거나 수정하지 않았는지 확인한다.

## 자동 검증 후보

- `npm run test:actions` - GPT Action 응답 계약과 preview payload를 확인한다.
- `npm run test:mcp` - MCP 생성 흐름과 widget 응답을 확인한다.
- 관련 Playwright 테스트 - 상세 화면, 지도 범례, 미리보기 이미지를 브라우저에서 확인한다.

## 미확인

- 실제 대표 입력은 구현 단계에서 새로 생성해야 한다.
- 2박 이상 대표 입력은 아직 정하지 않았다.
- 현재 문서 단계에서는 테스트 명령을 실행하지 않았다.
- 구현 단계에서 테스트 스크립트 이름과 범위는 package scripts를 확인한 뒤 확정한다.
