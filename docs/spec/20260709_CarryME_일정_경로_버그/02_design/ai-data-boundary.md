# AI 데이터 경계 설계

## 결론

호텔/숙소 판단은 AI 생성 단계의 책임이다.
행선지 stop의 역할과 다음 구간 이동수단도 AI 생성 단계의 책임이다.
코드는 호텔/숙소를 키워드, 레거시 역할값, 별도 배송 개념으로 보정하지 않는다.
구현 단계에서는 이 결정을 요구사항의 제약으로 고정하고, 코드가 의미를 재해석하는 흐름을 만들지 않는다.

## 이유

호텔/숙소 여부는 장소명 문자열만으로 안정적으로 판단하기 어렵다.
숙소 이름에는 호텔이라는 단어가 없을 수 있고, 반대로 호텔이라는 단어가 들어가도 여행상 의미가 숙박지가 아닐 수 있다.
따라서 코드가 장소명을 보고 적극 추론하면 일정 의도와 다른 경로가 만들어질 가능성이 커진다.

## 책임 경계

| 영역 | 책임 |
| --- | --- |
| AI 생성 단계 | 사용자 요청과 숙소 후보 맥락을 보고 호텔/숙소를 일정 안에 올바르게 구성한다. |
| AI 생성 단계 | `standardStops`와 `carrymeStops`에 `role`과 `mode`를 포함해 일자별 전체 이동 흐름을 만든다. |
| 정규화 단계 | AI가 준 일정 구조를 화면 데이터로 옮긴다. 호텔/숙소 의미와 행선지 역할을 새로 추론하지 않는다. |
| 상세 화면 | 이미 구성된 일정과 경로를 표시하고, 기존 장소 검색/상세 조회로 좌표를 확정하며, CarryME 경로 재계산/fallback을 처리한다. |
| 저장소 | 새로 생성되는 preview payload를 저장한다. 기존 저장값을 직접 고치지 않는다. |

## 명시적 비목표

- 코드가 `호텔`, `숙소`, `hotel`, `resort` 같은 문자열로 호텔/숙소를 적극 판단하지 않는다.
- 코드가 기존 레거시 역할값을 신뢰해서 요구사항 의미를 되살리지 않는다.
- 코드가 별도 배송 개념을 만들어 요구사항의 중심 개념을 바꾸지 않는다.
- 코드가 AI 생성 결과를 임의로 재해석해 호텔/숙소를 새로 지정하지 않는다.
- 코드가 index만 보고 첫 stop을 `출발지`, 마지막 stop을 `도착지`로 확정하지 않는다.
- 좌표 보강을 위해 새 장소 검색 체계를 만들지 않는다.

## AI 생성 설계 방향

AI 생성 단계는 호텔/숙소를 문맥상 분명히 표현해야 한다.
숙소 후보가 제공되면 후보 중 하나를 숙박지로 선택하고, 사용자가 숙소를 직접 제공하면 그 숙소를 기준으로 한다.
숙소가 미정이면 AI가 특정 호텔명을 지어내지 않고 미정 상태를 유지해야 한다.

AI 생성 단계는 각 day의 `standardStops`와 `carrymeStops`를 일자별 전체 이동 흐름으로 내려준다.
각 stop의 `role`은 `출발지`, `방문지`, `숙소`, `복귀지` 중 하나다.
각 stop의 `mode`는 다음 stop까지 이동할 대표 이동수단이며 `drive`, `transit` 중 하나다.
`walk`는 provider 내부 세부 도보 구간으로는 존재할 수 있지만, 웹에서 사용자가 선택하거나 AI가 행선지 간 대표 mode로 내려주는 값으로 쓰지 않는다.
마지막 stop은 다음 구간이 없으므로 mode를 생략할 수 있다.

`startPoint` 별도 필드는 두지 않는다.
출발지는 첫 stop의 `role: 출발지`로 표현한다.
마지막 날 복귀지는 마지막 stop의 `role: 복귀지`로 표현한다.

2일차 이상에서 출발지가 누락된 경우에는 전날 마지막 `숙소` role stop을 출발지 후보로 사용할 수 있다.
이는 이름 기반 추론이 아니라 AI가 이미 구조화한 role을 이용하는 제한된 fallback이다.
전날 숙소 role도 없으면 `확인 필요`로 보고 경로 재계산을 막는다.

## 구현 단계 주의점

기존 코드 식별자에 요구사항과 다른 이름이 남아 있을 수 있다.
구현 문서와 코드 변경에서는 해당 식별자를 내부 레거시 이름으로만 다루고, 요구사항 본문 용어로 끌어올리지 않는다.
필요하면 식별자 제거 또는 의미 중립 이름으로 변경하는 방향을 검토한다.

`PlanmeDraftRouteStop`과 AI schema는 role/mode를 보존할 수 있어야 한다.
`RouteStop` 또는 상세 화면 row로 변환할 때 role/mode/placeId/coordinate가 끊기지 않게 해야 한다.
좌표가 없는 장소는 기존 `/api/places/autocomplete`와 `/api/places/details` 흐름을 통해 확정한다.
좌표가 확정되지 않으면 provider path/polyline과 소요시간 계산을 실행하지 않는다.

## 리스크

- AI 생성 품질이 낮으면 화면은 정확한 호텔/숙소 의미를 새로 만들어낼 수 없다.
- 이 리스크는 코드 보정으로 해결하지 않는다.
- 구현 단계에서는 AI 입력 맥락과 출력 구조를 명확히 하는 쪽으로 다룬다.
